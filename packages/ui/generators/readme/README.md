# readme

Порождает `README.md` — один файл НА КАЖДЫЙ компонент отдельно (в отличие от
[`../barrel/`](../barrel/README.md), который агрегирует все компоненты в один файл). Движок —
`@probe-web/generators/scaffold` (тот же обход/шаблон/запись, что у `barrel`, только режим
"один файл на запись", а не агрегат).

**Это МЕХАНИЧЕСКАЯ половина документации — таблицы, не проза.** Прозу (объяснение, реальные
примеры использования) этот генератор не пишет и не может — она идёт отдельным заходом через
[`../prompt/`](../prompt/README.md) в ту же секцию `## Notes`, которую этот генератор не трогает.
Прогон одного `readme` без прохода по `prompt` — законченный компонент кита без объяснения, что он
делает и как им пользоваться, только сухие таблицы.

## Два источника данных, не один

- **`entity/passport.ts`** — РАНТАЙМ: части, состояния, `mark` (атрибут/псевдокласс, за который
  цепляется скин), настройки со значением по умолчанию.
- **`playground/index.ts`** (`editorInfo`) — РЕДАКТОРСКИЙ срез: `means` — человеком написанный
  смысл каждой части/состояния/настройки, плюс группа/род/размер (`group`/`genus`/`footprint`).

Тот же довод, что у самого паспорта (`PWEB-115`/`PWEB-118`) — два разных вопроса ("что это
физически выражает" и "что это значит для человека"), не один срез на оба.

Оба читаются ИСПОЛНЕНИЕМ файла (`@probe-web/generators/extract`, движок — `vite`), не разбором
текста: и паспорт, и `editorInfo` строятся вызовом функций (`definePassport`, `defineSettings()()`,
`defineEditorInfo`), и статический разбор означал бы заново реализовывать их логику.

`means` может быть плейсхолдером `"TODO"` — так заведено конвенцией `playground` (заполняет другой
агент), и это честный, не выдуманный текст: показывается как есть, не подменяется.

## Ручная зона, которая переживает регенерацию

Секция `## Notes` между маркерами `<!-- user:start -->`/`<!-- user:end -->` — единственное место в
файле, которое генератор НЕ перезаписывает. Движок — `@probe-web/generators/preserve`: перед
записью читается то, что сейчас лежит на диске по тому же пути, вырезается помеченный кусок и
склеивается со свежим авто-текстом. Нет файла или маркеры не найдены — остаётся плейсхолдер
шаблона, ничего не теряется, потому что терять было нечего.

Всё, что вне маркеров, регенерируется целиком при каждом прогоне — как и у `barrel`.

## Устройство

- **`readme.mjs`** — конфиг + сбор данных (`formatMark`, слияние паспорта с `editorInfo`) + склейка
  ручной зоны перед записью (`generateScaffoldFiles` + `mergeMarkedRegions` + `writeGeneratedFiles`,
  не `runScaffoldGeneration` — авто-запись движком здесь не подходит, слияние обязано случиться
  МЕЖДУ рендером и записью).
- **`templates/component-readme.md.hbs`** — сам текст: анатомия (часть → смысл), состояния
  (часть/состояние/`mark`/смысл), настройки (настройка/смысл/значение по умолчанию/`mark`), и
  секция `## Notes` с маркерами.

<h2 id="главное">🏠 Главное</h2>

🗄️ Служба, которая кладёт JSON и отдаёт обратно — используйте, если нужно хранить именованные
настройки (пресеты) любого вида и раздавать их по сети. 🧬 Один сквозной поток: конверт (label +
опциональные name/description/kind) → атомарная запись в базе → список без содержимого / запись
целиком по id. 🛠️ Средство, а не решение — служба не понимает, ЧТО лежит под `state`: разбор
формата остаётся у владельца конкретного `kind` (скин разбирает свой наряд, отбор — свой фильтр),
здесь только приём, хранение и раздача байтов.

Это `genus: service` — не библиотека, которую импортируют в свой процесс, а самостоятельный
сервис: у него есть свой бинарник, свой порт, свой сетевой контракт. Потребитель не собирает
из него механизм внутри себя (как с `engine`) — он ходит к уже поднятой службе по HTTP.

<h2 id="анатомия">🧩 Анатомия</h2>

🗺️ У сервиса нет экспортируемых функций — часть здесь означает именованную HTTP-ручку со своим
устойчивым адресом (метод + путь), а не подпуть поставки или кусок разметки.

| Часть | Адрес | Значит |
|---|---|---|
| Перечень | `GET /api/presets` | Все записи, без `state` |
| Перечень по виду | `GET /api/presets?kind=X` | Только записи с этим ярлыком — сравнение строки, не толкование |
| Чтение | `GET /api/presets/{id}` | Запись целиком, вместе с `state` |
| Создание | `POST /api/presets` | Новая запись — id и время выдаёт служба, `201` + `Location` |
| Замена | `PUT /api/presets/{id}` | Запись ВМЕСТО прежней с тем же id, одной атомарной транзакцией |
| Удаление | `DELETE /api/presets/{id}` | `204`, повторный вызов — `404`, не отказ по сути |
| Живость | `GET /healthz` | Не проксируется наружу — только докеру и тому, кто разворачивает |

📦 Внутри: `cmd/presets` — точка входа (окружение → база → сервер → сигналы). `internal/model` —
форма записи. `internal/limits` — числовые пределы. `internal/store` — bbolt-хранилище, вся логика
атомарности и пределов. `internal/api` — разбор конверта и HTTP-диспетчеризация. Публичного пакета
для импорта нет вовсе — вся поверхность фичи это сетевой контракт, а не Go-экспорт.

<h2 id="использование">🚀 Использование</h2>

**Поднять службу:**

```sh
go run ./cmd/presets
# слушает 127.0.0.1:8787, база — ./db/presets.db
```

**Положить пресет и получить его обратно:**

```sh
curl -s -X POST http://127.0.0.1:8787/api/presets \
  -H 'content-type: application/json' \
  -d '{"label":"Тёмная тема","name":"twitter-dark","kind":"skin","state":{"mode":"dark"}}'
# → 201, Location: /api/presets/<id>, тело — meta без state

curl -s http://127.0.0.1:8787/api/presets?kind=skin
# → { "items": [ { "id": "...", "label": "Тёмная тема", "name": "twitter-dark", "kind": "skin", "savedAt": "..." } ] }
```

**Заменить содержимое той же записи одним вызовом:**

```sh
curl -s -X PUT http://127.0.0.1:8787/api/presets/<id> \
  -H 'content-type: application/json' \
  -d '{"label":"Тёмная тема v2","name":"twitter-dark","kind":"skin","state":{"mode":"dark","accent":"#1da1f2"}}'
# → 200, id тот же, savedAt обновлён
```

**Устойчивая обвязка сверху** — `@web-core/skin/presets` (`createPresetsClient`,
`createPresetsSkinSource`): типизированный TS-клиент поверх этого же контракта, конкретный пример
того, как виды (`skin`) реально читают эту службу.

<h2 id="настройки">🎚️ Настройки</h2>

⚙️ Настраивает служебу окружение — тот, кто РАЗВОРАЧИВАЕТ, а не тот, кто пишет код (`cmd/presets`).

| Переменная | По умолчанию | Значит |
|---|---|---|
| `PRESETS_DB` | `./db/presets.db` | Путь к файлу базы (bbolt) |
| `PRESETS_PORT` | `8787` | Порт |
| `PRESETS_HOST` | `0.0.0.0` | Адрес |
| `PRESETS_MAX_RECORD_BYTES` | `1048576` (1 МиБ) | Предел размера ОДНОЙ записи |
| `PRESETS_MAX_RECORDS_PER_KIND` | `200` | Предел числа записей ОДНОГО вида — список выбирают глазами |
| `PRESETS_MAX_TOTAL_BYTES` | `67108864` (64 МиБ) | Предел занятого объёма всего хранилища |
| `PRESETS_MAX_LABEL_CHARS` | `120` | Предел длины `label` |
| `PRESETS_MAX_DESCRIPTION_CHARS` | `1000` | Предел длины `description` |

<h2 id="состояния">🎛️ Состояния</h2>

🚦 Состояние здесь — не рантайм служебного процесса, а код `error` в теле отказа: настоящая,
ловимая строка, а не рантайм-исключение, которое нужно перехватывать по тексту.

| HTTP | `error` | Значит |
|---|---|---|
| `400` | `label_required` | Нет `label`, или он пуст, или не строка |
| `400` | `label_too_long` | `label` длиннее предела |
| `400` | `bad_name` / `bad_kind` | `name`/`kind` не подходят под форму `^[a-z0-9][a-z0-9-]{0,31}$` |
| `400` | `bad_description` / `description_too_long` | `description` не строка / длиннее предела |
| `400` | `state_required` | В конверте нет ключа `state` вообще (даже `null` — это законное значение) |
| `400` | `bad_json` / `bad_request` | Тело — не JSON / не объект |
| `404` | `not_found` | Такой записи нет |
| `405` | `method_not_allowed` | Путь есть, метод не тот (заголовок `Allow`) |
| `409` | `name_taken` | Машинное имя занято другой записью ЭТОГО ЖЕ вида |
| `409` | `storage_full` | Кончились места в списке вида или байты всего хранилища |
| `413` | `too_large` | Одна запись больше предела |
| `500` | `internal` | Неожиданная поломка — причина в лог, наружу только текст для человека |

<h2 id="io">🔌 IO</h2>

<h3 id="io-вход">📥 Вход</h3>

Конверт `POST`/`PUT` — единственная форма входа, и `state` в ней не разбирается вообще:

| Поле | Обязательно | Форма |
|---|---|---|
| `label` | да | непустая строка, ≤ `LabelChars` |
| `name` | нет | `^[a-z0-9][a-z0-9-]{0,31}$` |
| `description` | нет | строка, ≤ `DescriptionChars` |
| `kind` | нет | та же форма, что у `name` |
| `state` | да (ключ должен быть, значение — любое) | произвольный JSON, байты не трогаются |

<h3 id="io-выход">📤 Выход</h3>

| Действие | Отдаёт |
|---|---|
| `GET /api/presets(?kind=)` | `{ items: Meta[] }` |
| `GET /api/presets/{id}` | `Meta & { state }` |
| `POST` / `PUT` | `Meta` (без `state`) |
| Любой отказ | `{ error: string, message: string }` |
| `GET /healthz` | `{ ok, presets, bytes, limits }` |

`Meta` — `{ id, label, name?, description?, kind?, savedAt }`, где `savedAt` — RFC3339 с
наносекундами.

<h2 id="сборки">🏗️ Сборки</h2>

🧪 Своих потребителей у службы нет — она их не знает. Доказывается пробами на реальном HTTP-слое
и реальной базе (37 тестов, 2 файла, зелёные под `-race`), плюс двумя мутациями, снятыми руками.

| Сборка | Что доказывает |
|---|---|
| `internal/store/store_test.go` | CRUD, атомарность `Replace`, пределы (запись/вид/объём целиком), opaque-проход `state`, конкурентные создания под гонкой (`-race`) |
| `internal/api/handler_test.go` | Полный HTTP-контракт: каждое действие, каждый отказ своим кодом, CORS на каждом ответе, `Location` на создании |
| Мутация: изоляция предела по виду | Снял фильтр по `kind` в счётчике — проба `TestRecordsPerKindLimitDoesNotStarveOtherKinds` покраснела |
| Мутация: изоляция имени по виду | Снял `kind` из ключа индекса имён — проба `TestNameUniquePerKindNotGlobal` покраснела |
| Живой прогон | `go run ./cmd/presets` + `curl` — create→list→get проходят по-настоящему, не только под тестом |

<h2 id="рецепт">🎨 Рецепт</h2>

🧩 У этой фичи ВСЯ логика вида — съёмный слой, и это не частный случай, а сама причина, по которой
служба вообще существует. Она не носит в себе ни одного `kind` и не может: понимание, что значит
`skin` или `filter`, целиком живёт СНАРУЖИ, у владельца вида.

```ts
// packages/skin/src/presets — рецепт для ОДНОГО вида (`outfit`), написанный владельцем скина.
// Сервис не знает об `Outfit` ничего — для него это байты под ключом `state`.
import { createPresetsClient, PRESET_KIND } from "@web-core/skin/presets";

const client = createPresetsClient({ url: "http://127.0.0.1:8787/api/presets" });
await client.save(PRESET_KIND.outfit, "brand", outfit);
```

Второй вид (например, `filter` у зоны `tables`) — второй такой же клиент, с нулём правок здесь.

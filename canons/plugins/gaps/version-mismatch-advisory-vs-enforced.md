# Расхождение: несовпадение версии — предупреждать или отклонять?

**Вопрос (заказ P2, вопрос 5):** что среда ОБЯЗАНА сделать с расширением, объявившим несовместимую версию?

Два устоявшихся источника отвечают **противоположно**. Оба приводятся; выбор не делается.

## Ответ A — советующее, не блокирует (npm)

> Unless the user has set the `engine-strict` config flag, this field is advisory only and will only produce warnings when your package is installed as a dependency.
> — npm package.json `engines` (`sources/npm-package-json-engines.md`)

Несовпадение по умолчанию не мешает установке: печатается предупреждение. Жёсткий отказ — отдельный, по умолчанию выключенный флаг. Допускается и `*`/пропуск («любая версия»).

## Ответ B — обязательная граница, `*` запрещён (VS Code)

> engines … An object containing at least the vscode key matching the versions of VS Code that the extension is compatible with. Cannot be *.
> — VS Code Extension Manifest (`sources/vscode-extension-manifest.md`)

`engines.vscode` обязателен, открытый диапазон `*` запрещён; заявить «совместимо с любой версией» нельзя — граница должна быть названа.

## Почему это оставлено расхождением, а не сведено

Это два разных ответа на один вопрос, и каждый разумен в своей среде: пакетный менеджер общего назначения (npm) склоняется к «не мешать пользователю», расширяемый продукт с магазином (VS Code) — к «не пускать заведомо несовместимое». Разница не в качестве нормы, а в том, кто несёт риск несовместимости — потребитель или платформа. Выбор между этими политиками — решение владельца среды, а не факт рынка.

## Не перебрано (можно закрыть добором)

- OSGi: как фреймворк ведёт себя с бандлом, чьи версионные требования (`Import-Package` version range) не разрешаются, — вероятно, бандл остаётся в `INSTALLED` и не переходит в `RESOLVED`; дословно в этот заход не выписано.
- WebExtensions: поведение при `manifest_version`, который браузер не поддерживает.

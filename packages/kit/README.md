# @omnifield/probe-web-kit

Фреймворк-времянка локации `probe-web`: Solid + Vite за тремя точками. То, что продукты
**импортируют**, а не копируют.

Скелет продукта кладёт соседняя зона `starter` (обвес `@omnifield/probe-web`), и кладёт
**один раз** — класс `placed-once`, файлы у потребителя больше не обновляются никогда.
Поэтому здесь всерьёз сделана только граница, а всё за ней — черновик, который заменят,
когда сюда переедет настоящая заготовка фронта.

Контракт шва целиком — `kb:PROBEWEB-2`. Он ведётся architect'ом; эта страница его не
заменяет, а пересказывает со стороны пакета.

## Три точки наружу — и больше ничего

| точка | что даёт |
|---|---|
| `@omnifield/probe-web-kit` | `mount(root)` — рантайм |
| `@omnifield/probe-web-kit/vite` | `defineConfig()` — готовый конфиг Vite |
| `@omnifield/probe-web-kit/tsconfig` | базовый `tsconfig` файлом пакета |

Плюс **DOM-контракт**: страница даёт `<div id="root"></div>`, `mount()` ищет `#root` сам.

Всё остальное внутри пакета — внутреннее и ломается свободно. Эти три точки и `#root`
**заморожены навсегда**: их зовут файлы, лежащие у потребителей, и починить их выпуском
пакета нельзя — файлы уже не наши. Понадобилась четвёртая точка — это разговор с
architect, а не решение внутри зоны.

## Как это выглядит у потребителя

```ts
// vite.config.ts
import { defineConfig } from "@omnifield/probe-web-kit/vite";
export default defineConfig();
```

```json
// tsconfig.json
{ "extends": "@omnifield/probe-web-kit/tsconfig", "include": ["src"] }
```

```tsx
// src/main.tsx
import { mount } from "@omnifield/probe-web-kit";

mount(() => <h1>hello, probe-web</h1>);
```

Про solid-плагин и версию Vite потребитель не знает: и то, и другое живёт за
`defineConfig()` и меняется нашим выпуском, без правки его файлов.

Нет `#root` — `mount()` падает с внятным сообщением, а не оставляет пустую страницу молча.

## Зависимости у потребителя

`solid-js` и `vite` объявлены **peer**: их ставит приложение, а не kit. Причина у каждой своя
и обе неустранимые:

- `vite` потребитель запускает как команду (`vite build`), а бинарь транзитивной зависимости
  в его `node_modules/.bin` не попадает;
- `solid-js` он импортирует напрямую из своего JSX, и при изолированной раскладке pnpm
  транзитивный пакет из его файлов не разрешается.

Практическое следствие для соседней зоны: **манифест скелета обязан перечислять оба** рядом
с `@omnifield/probe-web-kit`. Диапазоны версий задаёт kit — в `peerDependencies`.

`vite-plugin-solid` — обычная зависимость kit: его зовём мы, и потребитель про него не знает.

## Perf-трейсы

По умолчанию молчат, включаются явным флагом — до вызова kit:

```ts
globalThis.__PROBE_WEB_KIT_TRACE__ = true;
```

Автоопределение по `import.meta.env.DEV` сознательно не используется: kit приезжает
зависимостью, а подстановку в файлы из `node_modules` Vite не делает — условие оказалось бы
вечно ложным, то есть трейсы были бы мёртвым кодом (проверено сборкой, 2026-08-08).

## Разработка

```sh
pnpm install     # ставит и пакет, и тестовое приложение (workspace)
pnpm run build   # tsc → dist
pnpm run lint    # проверка типов пакета и тестов
pnpm test        # сборка + все проверки
```

Машинного pre-commit в репозитории нет — каденс `этап → проверка → коммит` держится на
агенте: `build` + `lint` + `test` руками перед каждым коммитом.

### Что проверяют тесты

- `test/build.test.ts` — **собирает настоящее приложение** (`test/fixture`, подключает kit
  как установленный пакет через `workspace:*`) и проверяет, что в разметке появился
  отрендеренный узел. «Функция экспортируется» и «страница собралась» — разные утверждения;
  подтверждаем второе. Здесь же `tsc` прогоняет приложение на базе из точки `/tsconfig`.
- `test/runtime.test.ts` — DOM-контракт `#root`, внятное падение без него, трейсы.
- `test/surface.test.ts` — `pnpm pack` и разбор тарбола **перечнем**: три точки объявлены,
  каждая цель `exports` реально лежит внутри, исходники и тесты потребителю не едут.

## Версия и публикация

Версию поднимает **architect при публикации**, не владелец зоны в коммите. Реестр —
GitHub Packages, метка `latest` (`kb:PROBEWEB-2`).

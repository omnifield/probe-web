# @omnifield/probe-web-runtime

Рантайм probe-web: **`mount()` и контракт `#root`** — то, что зовёт скелет приложения у
потребителя. Первая из четырёх замороженных точек выпуска (контракт зон — `kb:PROBEWEB-4`).

Пакет не знает ни про сборку, ни про стили, ни про компоненты: build-инструментов в его
зависимостях нет и быть не может — ради этого зона и отделена от `build`.

## Поверхность — ровно одна точка

```ts
import { mount } from "@omnifield/probe-web-runtime";

export function mount(root: () => JSX.Element): void;
```

Всё остальное в пакете — внутреннее и ломается свободно.

**Это не «пока что одна точка».** `main.tsx` едет к потребителю классом `placed-once`:
положен один раз и не обновляется никогда. Значит вызов в нём живёт вечно ровно в той форме,
в какой его туда положили, и добавить сюда второй экспорт — решение architect, а не зоны.

## Контракт `#root`

Точку монтирования рантайм ищет **сам** — элемент с `id="root"` в документе:

```html
<div id="root"></div>
```

Идентификатора нет в сигнатуре намеренно: передай его аргументом — и заодно с вызовом
заморозится способ разметки страницы, а он обязан двигаться. Элемента нет — `mount()`
**падает с внятным сообщением**, а не рисует молча в пустоту:

```
[probe-web-runtime] mount(): в документе нет элемента #root.
Точку монтирования рантайм ищет сам — добавь в index.html <div id="root"></div>.
```

`#root` — часть замороженной поверхности наравне с самим экспортом. Менять его нельзя без
мажора и разговора с architect.

## Владение и очистка

`render()` из `solid-js/web` создаёт владеющий контекст (`createRoot`) и возвращает `dispose`.
Дока Solid прямо предупреждает: **без явного `dispose` вычисления не управляются и текут**
(фонд `solidJS/sources/solid-docs-ownership.md`).

Что решено и почему:

- **Наружу `dispose` не отдаётся.** Тип точки заморожен как `void`; вернуть ручку — значит
  изменить замороженную поверхность, а это разговор с architect, не решение внутри зоны.
- **Но и не выбрасывается.** Ручку держит сама зона — `WeakMap` «узел-хозяин → `dispose`».
  Модульная переменная тут не годится: она пережила бы сам узел и вечно держала бы замыкание
  над оторванным от документа деревом. Умер ключ-узел — умерла запись.
- **Повторный вызов на том же `#root`** (HMR, перезапуск) сначала **уничтожает** прежний
  корень и только потом монтирует новый. Инвариант зоны — «один документ, одно приложение»:
  `#root` в контракте один, и складывать в него корни стопкой значит держать живыми
  вычисления, до которых уже никто не дотянется.
- **Страница закрывается — уничтожать нечего:** корень умирает вместе с документом, и
  вешать ради этого `pagehide` было бы обрядом, а не очисткой.

Понадобится потребителю управляемый `dispose` (микрофронтенды, несколько приложений на
странице) — это заявка на изменение контракта, и адресат её architect.

## Perf-трейсы

Молчат по умолчанию, включаются явным глобальным флагом:

```js
globalThis.__PROBE_WEB_RUNTIME_TRACE__ = true;
// [probe-web-runtime] mount — 1.83ms
```

Автоопределения по dev-режиму сборщика нет намеренно: пакет приезжает потребителю
зависимостью, а подстановку в файлы из `node_modules` Vite не делает — условие осталось бы
вечно ложным, то есть трейсы были бы мёртвым кодом.

## Установка

`solid-js` — **peer-зависимость**: две копии Solid в дереве ломают реактивность.

```
pnpm add @omnifield/probe-web-runtime solid-js
```

ESM-only, `"type": "module"`, `sideEffects: false`, в тарбол едет только `dist` и эта дока.

## Раскладка

```
packages/runtime/
├── src/
│   ├── index.ts            # mount() — единственная точка наружу
│   └── trace.ts            # perf-трейсы, ВНУТРЕННЕЕ (в exports не объявлено)
├── test/
│   ├── mount.test.tsx      # приложение поднимается в DOM (jsdom + JSX-трансформ)
│   └── surface.test.ts     # поверхность и тарбол — перечнем, а не на глаз
├── tsconfig.json           # конфиг самого пакета (базу потребителю отдаёт зона build)
├── tsconfig.build.json     # эмит dist по src
└── vitest.config.ts        # два проекта: браузерный mount и сборочный surface
```

## Проверки

```
pnpm run typecheck   # tsc --noEmit
pnpm run build       # dist
pnpm test            # сборка + оба проекта vitest
```

Тест зоны поднимает **настоящее** приложение на Solid в JSDOM и утверждает отрендеренный узел
в `#root`, отдельными кейсами — живую реактивность после монтирования, уничтожение прежнего
корня при повторном вызове и внятный отказ без `#root`.

Официальная `@solidjs/testing-library` здесь сознательно **не** используется (сверено
2026-08-08, фонд `solid-testing-library`): её `render` создаёт свой контейнер, а предмет
проверки ровно обратный — что рантайм находит точку монтирования сам, в документе. JSX-трансформ
и `resolve.conditions: ["development", "browser"]` взяты из доки как предписано.

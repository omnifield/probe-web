# ❓ FAQ

Короткие ответы на конкретные вопросы, которые уже возникали по зоне `build`. Не общая
документация (она в [`README.md`](./README.md)) и не план (он в [`ROADMAP.yaml`](./ROADMAP.yaml))
— только факты, каждый проверен на практике. Вопросы про конкретную тему — в её собственном
`src/<тема>/FAQ.md`.

---

### Почему одна оснастка отдаёт конфиг и для приложения, и для библиотеки — не два пакета?

**Коротко: одна оснастка на разные цели потребления — рыночная форма, не изобретение здесь.**

Раньше каждая библиотечная зона (`ui`, `skin`, `assembly`) несла собственный
`scripts/build.mjs` поверх esbuild — почти дословный повтор в нескольких копиях, который никто
не заметил бы разошедшимся. `@vite-config`-пакет одним набором функций под и приложение, и
библиотеку — форма Turborepo и любого монорепо-стартера с общим `vite-config`. Прежнее чтение
`PROBEWEB-4` («направление зависимостей одностороннее, `ui` не вправе зависеть от `build`»)
было перестраховкой уже на первом же примере: одна оснастка на разные цели потребления — это и
есть paved road, а не два держателя одного и того же знания.

---

### В зоне раньше был `test/` с настоящими пробами (сборка приложения, дев-сервер, тарбол) — где он?

**Коротко: снесён коммитом `f807343` («replaced by apps/panel», PWEB-124), README тогда не поправили.**

`git log -- packages/build/test` показывает, что папка была снесена вместе с `tools/dev-nav`
при переходе на `apps/panel`. Часть удалённого была настоящими пробами именно этой зоны (сборка
тестового приложения конфигом `/vite`, реальные HTTP-запросы к дев-серверу, разбор тарбола
`pnpm pack`), не связанной с `dev-nav` впрямую — задета попутно. Урок тот же, что уже ловился в
ките (`packages/ui/src/button/FAQ.md`): README и код расходятся тихо, если поправить один и
забыть другой. Статус — в `ROADMAP.yaml`, `id: rebuild-test-suite`.

# Зона `skin` — готовые оформления для безголового кита

**Что здесь лежит:** правила вида для примитивов зоны `ui` (только CSS) и пресеты — наборы
значений вида, отчуждаемые от стенда.
Контракт зоны — `kb:PROBEWEB-11`, правила зон `products/` — `kb:PROBEWEB-5`.

```
src/skin/      поставка: base.css (объявление слоя) + по файлу на семейство + сборный skin.css
src/presets/   пресеты как данные: встроенные, модель, хранилище своих
src/icons/     ядро набора значков как данные: имена и причина, по которой значок в ядре
src/playground/ стенд: витрина, кейсы, панель настройки скина
test/          пробы: зацепки, литералы, слои, темы, применение к узлу
```

## Как это подключается

```ts
import "@omnifield/probe-web-style/base.css";   // роли и производные шкалы
import "@omnifield/probe-web-style/themes.css"; // ступени палитры
import "@probe-web/skin/skin.css";              // весь кит одной строкой
```

Нужна только кнопка — берите `base.css` (он объявляет слой) и `button.css`. Раздельные подпути
существуют ровно для этого.

**Снимается удалением импорта.** Кит без нас — голые примитивы с зацепками `data-slot`, ровно
то, чем он и является. Это первое правило зоны, и его стережёт проба, а не обещание.

## Пресеты — вид одним указанием

**Пресет** — полный набор значений вида: семена шкал, правки тёмной пары, скругление, шаг
интервалов, базовый кегль, высота контрола, плотность. Подключается целиком, а не по одной вещи.

```ts
import "@probe-web/skin/presets/twitter.css";
```

```html
<html data-theme="twitter">   <!-- тёмная пара — классом dark, как у базовой темы -->
```

Всё. Ни сборки, ни строки JS: **CSS первичен**, потому что «взять этот вид» должно работать
указанием файла и атрибута. Описание объектом (`src/presets/`) — источник, из которого файл
рождается; потребителю нужен файл.

**Пресеты живут в службе, локальных нет.** В коде остаётся одно СЕМЯ (`twitter`): им засевается
пустая служба (`pnpm run seed:presets`), из него же рождается файл поставки. Второй «встроенный»
означал бы локальный перечень рядом со служебным, а два перечня расходятся молча.

**Удалить можно любой пресет, включая семя** — они общие, и «своих» среди них нет. Удаление
спрашивает подтверждение: пресет уходит из службы у ВСЕХ. Удалили последний — оформления нет
вовсе, остаётся голый кит, а семя возвращается одной командой.

**Тему задаёт ХОЗЯИН, зона её читает.** Пульт или приложение, в которое встроена зона, ставит
`data-theme` на корень — стенд его принимает и не перебивает. Тронули ручку в панели вида — зона
отвязалась (`data-look-own="true"`, пульт это уважает), и об этом сказано строкой. Состояний
ровно два: слушаю хозяина / своя тема; своё живёт до перезагрузки страницы.

**Механика от пресета не меняется.** Что в пресет намеренно **не** входит:

- светлый/тёмный режим — выбор пользователя, один пресет обязан работать в обоих;
- варианты кнопок и прочая поверхность зоны — иначе пресет менял бы поведение, а не вид;
- подключено ли оформление вообще — это не поле пресета, а следствие его наличия (ниже).

**Оформление следует за пресетом, своей ручки у него нет.** Есть пресет — правила вида стоят;
нет ни одного — стенд снимает `skin.css`, и остаётся голый кит. Отдельный тумблер в панели был и
убран (решение user 2026-08-18): он позволял состояние «правила вида есть, пресета нет» — значения
при этом приходили из умолчаний базы, и человек видел одетые компоненты, которых никто не одевал.
Голый кит (`kb:SKIN-7`, инвариант 4) от этого не пропал, а стал честнее: он ровно там, где пресета
нет. Держит правило `test/knobs-service.test.ts` с обеих сторон — и «есть пресет — одето», и «нет
пресета — снято».

**Свой пресет** делается из любого другого: покрутили ручки на стенде — он стал изменённым, —
сохранили под своим именем, и он встал в список наравне с остальными.

**Пресеты живут в службе, а не в браузере.** Стенд читает перечень из `products/presets`
(`?kind=skin`), туда же уезжает сохранённое — и его сразу видят коллеги. Браузерного хранилища
в зоне нет вовсе: черновик, невидимый никому, не нужен, а два хранилища расходятся. Семя кладётся
в службу командой `pnpm run seed:presets`.

**Черновик и общее разведены СОСТОЯНИЕМ, а не вторым складом.** Черновик — это «пресет изменён
ручками»: он живёт в памяти вкладки, показан плашкой и снимается кнопкой «Вернуть». Общее — то,
что уехало в службу: сохранили, и это видят все. Второго склада нет намеренно — расходиться было
бы нечему только у одного из двух.

**Службы нет — стенд не ломается, но и не врёт.** Перечень пуст, а раз пресета нет — нет и
оформления: остаётся голый кит. Сохранить нельзя, и кнопка выключена. Человеку называется причина
**с адресом** и команда подъёма службы — адрес это единственная часть, по которой он может
что-то сделать. Три состояния говорятся врозь, потому что лечатся врозь: служба отвечает и
перечень есть · служба отвечает, но пуста (`pnpm run seed:presets`) · службы нет
(`pnpm --filter @probe-web/presets start`).

Неверная подсказка хуже молчания: панель однажды обещала «перечень встроенный», хотя запасного
перечня в зоне нет, — человек видел пустой список и обещание списка. Ловит это
`test/knobs-service.test.ts`, и ловит на состоянии, а не на проводе.

**Идентификатора два, и они не путаются:** служба выдаёт свой (UUID) — он опознаёт ЗАПИСЬ, по
нему её удаляют; в `data-theme` уезжает имя ТЕМЫ, оно читаемое и совпадает с именем файла
поставки. `data-theme="5fdbea2d-4afc-…"` человеку не говорит ничего.

Генерация файлов — `pnpm run build:presets`. Сгенерированное лежит в репозитории и сверяется
пробой: расхождение файла с моделью — красный прогон с указанием перегенерировать.

**Строку собирает БАЗА, а не зона** (`themeModelToCss` из `@omnifield/probe-web-style`, решение
`kb:PROBEWEB-15`). Своего генератора здесь нет и заводить его нельзя: две реализации из одной
модели дают два результата, и расходятся они молча — в день, когда база улучшит формулу ступеней.
Зона отвечает за МОДЕЛЬ пресета — название, происхождение, ручки, признак «изменён», — и отдаёт
базе её узкую часть одной функцией `modelOf()`. Из неё же рождаются и файл поставки, и запись в
службе. Возврат второго генератора ловит проба `test/presets-css.test.ts`.

## Значки — CSS-маска, а не компонент

```ts
import "@probe-web/skin/icons.css";
```
```html
<span data-icon="check" aria-hidden="true"></span>
```

`aria-hidden` обязателен: значок — картинка без текста. Если значок **единственное** содержимое
кнопки, кнопке нужна подпись (`aria-label`) — WCAG 2.2, 4.1.2 Name, Role, Value.

**Два свойства, ради которых форма и выбрана:** размер `1em` — значок сам следует за кеглем
контрола и за `data-size`; цвет `currentColor` — значок берёт роль у того, внутри чего стоит. Ни
одного правила «в мелкой кнопке значок мельче» в оформлении нет и не нужно.

**Своя иконка — одна строка,** и она встаёт наравне со встроенными:

```css
[data-icon="моя-штука"] { --icon: url("/icons/моя-штука.svg"); }
:root { --icon-check: url("/icons/своя-галочка.svg"); }   /* заменить встроенный */
```

Правило потребителя лежит вне слоя и потому побеждает наше без `!important`.

Источник картинок — **Lucide** (ISC, 1836 значков, сетка 24, обводка 2), но в поставку он не
тянется: `@iconify-json/lucide` стоит в `devDependencies`, а `pnpm run build:icons` выпускает
готовый `src/skin/icons.css`. У потребителя ни строки JS. **В ядре 46 значков — 29 КБ**, каждый с
названной причиной; весь набор как CSS весил бы 987 КБ, поэтому в ядро попадает то, что нужно
самому интерфейсу, а остальное добирается по имени тем же генератором.

Два узла кита значок получают сами: `select-icon` и `combobox-icon` — там, где kobalte рисует
текстовый глиф `▼`. Открывашкам (`accordion-trigger`, `collapsible-trigger`) шеврон добавляется
`::after` и поворачивается в раскрытом состоянии. И то, и другое **уступает потребителю**: поставил
свой значок внутрь — наше правило снимается.

## Тяжёлые компоненты — тот же механизм

```ts
import "@probe-web/skin/tables.css";   // таблица зоны `tables` одной строкой
```

Отдельно от `skin.css`: взявший только кит не должен получать правил таблицы, которой у него
нет. Внутри — `base.css` (слой), `icons.css` (значки) и семейства.

**Механика не изменилась ни на строку.** `tables` пришла к тому же канону (`kb:SKIN-1`): перечень
зацепок выписан руками и уехал в поставку данными (`src/slots.json`), состояния объявлены
атрибутами и перечислены. Мы цепляемся за имена и читаем состояния — `aria-sort`, `data-pinned`,
`data-format`, `data-missing`, `data-depth`.

**Части на примитивах кита одевает кит.** Списки, галки и поля таблицы несут оба имени
(`data-slot="select table-pager-size-select"`), и правило кита применяется само. Адрес даёт сам
сосед — `kitBacked` в его обещании; проба это читает и не считает такие части долгом.

**Одето всё, что показывается человеку:** `table` (41 зацепка), `filter` (55, из них 26 одел
кит), `chart` (16). Долг — ноль. Переходник (`adapter`) не одевается **по решению**: это
внутренний инструмент зоны, человеку он не показывается и состояний намеренно не обещает.
Прогон печатает долг и решения отдельно — смешать их значило бы вечно показывать недоделку там,
где договорённость.

График красится категорийной шкалой базы (`--chart-1…5`) по номеру ряда, а различать ряды одним
цветом нельзя (WCAG 1.4.1) — поэтому линии получают ещё и рисунок штриха, а легенда повторяет
его метиной.

## Три правила, которые нельзя нарушать

1. **Кит остаётся голым.** `skin` не правит `ui`. Зависимость односторонняя: мы знаем про кит,
   кит про нас — никогда. В поставке нет ни одного JS-модуля.
2. **Цепляемся за `data-slot`.** Имена классов и структура DOM — внутреннее дело кита; зацепки
   объявлены его обязательством (`packages/ui/test/slot-list.ts`).
3. **Ни одного значения литералом.** Цвета, скругления, длительности, размеры, слои — только
   токенами слоя `style`. Не хватает токена — заявка, а не литерал на месте.

## Варианты и размеры — публичная поверхность зоны

Кит безголовый и пропов вида не имеет. Вариант выбирает **потребитель атрибутом**, оформление
его читает:

```tsx
<Button>Сохранить</Button>                          {/* основное действие */}
<Button data-variant="outline">Отмена</Button>       {/* парное */}
<Button data-variant="danger" data-size="sm">Удалить</Button>
```

| `data-variant` | когда |
|---|---|
| нет атрибута | основное действие; простая разметка сразу даёт рабочий вид |
| `soft` | частое, но не главное действие |
| `outline` | парное действие рядом с основным |
| `ghost` | плотный ряд, где рамки создают шум |
| `danger` | необратимое действие |
| `danger-outline` | необратимое, но не главное |

`data-size`: `sm` · без атрибута (средний) · `lg`.

**Имя варианта — обещание.** Потребитель ставит его в разметку, и удаление имени ломает ему вид.
Перечень закрыт и стережётся пробой с двух сторон: объявленное обязано быть одето, одетое —
объявлено. Неизвестное значение атрибута кнопку не ломает: она остаётся в дефолтном виде.

Отдельная проба считает **контраст подписи на фоне для каждого варианта**, в обеих парах тем, и
пары читает из самого CSS, а не из списка рядом с проверкой. Иначе подмена роли в оформлении
прошла бы молча: проба продолжала бы проверять свой список.

## Ловушки одевания — каждая оплачена ошибкой

Это не свод хороших манер, а список того, на чём зона уже спотыкалась. Каждый пункт стоил
захода или правки после показа user.

### 1. Интерактивная область обязана совпадать с видимой

Триггер подсказки стоял в flex-колонке. Колонка растягивает детей по ширине — область наведения
вышла на всю панель, и подсказка всплывала от пустого места рядом с заголовком.

**Что делать:** любой элемент, у которого есть реакция на указатель или фокус (триггер, ссылка,
кнопка-иконка), внутри `flex`/`grid`-контейнера получает `inline-size: fit-content` и
`align-self`, либо задаётся не растягивающимся по природе. Проверка простая: границы наведения
должны быть там, где нарисовано.

### 2. Зацепка на узле бывает СПИСКОМ — точное равенство мимо неё

`<DialogTrigger as={Button}>` рендерит один узел, и на нём оба имени:
`data-slot="button dialog-trigger"`. Под `[data-slot="button"]` такой узел не попадает —
оформление кнопки просто не применяется, и ничего при этом не падает.

**Что делать:** читать зацепку списком — `[data-slot~="button"]`. Одиночному значению `~=` не
мешает, поэтому в поставке точного равенства нет ни одного, и это стережёт проба.

### 3. На составном узле наш вид обязан уступить кнопке

Кит собирает зацепки у девяти примитивов, где композиция реальна: кнопка, кнопка-переключатель,
ссылка и шесть триггеров. Файлы этих семейств идут после `button.css`, специфичность равная —
побеждает порядок, то есть НАШ вид. Что из этого выходит:

| разметка | без исключения | как надо |
|---|---|---|
| `<PopoverTrigger as={Button} data-variant="danger">` | нейтральный повтор триггера съедает вариант | вид кнопки, вариант работает |
| `<Link as={Button}>` | брендовый текст с подчёркиванием на сплошной заливке | вид кнопки, подчёркивания нет |
| `<CollapsibleTrigger as={Button}>` | `inline-size: 100%`, `border: 0`, `background: none` сносят кнопку | вид кнопки, поворот значка остаётся |
| `<Toggle as={Button} data-variant="outline">` | наш вид вместо выбранного варианта | вид кнопки + НАША нажатость |

**Что делать:** правила ВИДА исключают составной узел —
`[data-slot~="popover-trigger"]:not([data-slot~="button"])`. Правила СОСТОЯНИЯ (`[data-pressed]`,
`[data-expanded]`, `[data-disabled]`) исключения не несут: вид на составном узле даёт кнопка, а
поведение примитива показываем мы. Граница ровно здесь, и её стережёт реестр в
`test/hooks.test.ts` — с двух сторон, чтобы забытая запись не прошла молча.

Голый триггер при этом продолжает выглядеть контролом: повтор вида кнопки у него остаётся —
это цена независимых подпутей, и одевать семейство целиком требует канон (`kb:SKIN-1`).

Одно следствие для потребителя: у составного переключателя берите НЕ дефолтный вариант.
Дефолтная кнопка сама сплошная брендовая и читалась бы нажатой всегда.

### 4. Неизвестное имя значка даёт ЗАКРАШЕННЫЙ КВАДРАТ

`mask-image: none` означает «маски нет» — и заливка `currentColor` красится целиком. То есть
опечатка в имени значка даёт не пустоту, а чёрный прямоугольник, и читается это как поломка
оформления, а не как ошибка в разметке.

**Что делать:** маска читается с пустым фолбэком — `mask-image: var(--icon, var(--icon-empty))`,
где `--icon-empty` это пустой SVG. Стережёт проба `test/icons.test.ts`.

### 5. Часть, требующая контекста пункта, вне пункта роняет kobalte

`DropdownMenuItemLabel` внутри `DropdownMenuSubTrigger` — открывашка подменю не является пунктом
меню. Ошибка приходит в консоль, а меню не открывается ВОВСЕ. Страница при этом жива, и по виду
кажется, что «просто ничего не происходит».

### 6. Форма несёт смысл, и её нельзя терять при смене темы

Флажок с крупным семенем скругления (у нашей палитры `1.3rem`) превращался в круг и становился
неотличим от варианта группы. Квадрат — «выбери сколько угодно», круг — «выбери одно».

**Что делать:** там, где форма различает поведение, ставить потолок:
`border-radius: min(var(--radius-xs), 0.35em)`.

### 7. Узел значка может быть НЕ пуст

kobalte кладёт в `select-icon` символ `▼` по умолчанию. Оформление чертило поверх него свой
шеврон границами — на экране складывались обе фигуры.

**Что делать:** не чертить поверх. Либо оформлять то, что лежит внутри (место, кегль, цвет,
поворот), либо ЗАМЕНИТЬ глиф значком — так и сделано сейчас: текст уезжает за край
(`overflow: hidden; text-indent`), а на его месте рисуется маска. Метрики шрифта при этом
остаются, на них держится размер `1em`.

Заменять можно **только дефолт кита**. Содержимое потребителя неприкосновенно, поэтому правило
снимается, как только внутри появляется элемент: `:not(:has(*))`.

### 8. Место и зазор всплывающих задаёт позиционировщик, а не оформление

`gutter`, `placement`, `shift`, `flip`, `sameWidth` — опции на КОРНЕ (`Select`, `Popover`,
`Tooltip`, `DropdownMenu`). Отступ в CSS спорит с floating-ui за ту же величину, которую тот
переписывает каждый кадр.

### 9. Семена настройки ставятся на КОРЕНЬ документа

Производные шкалы и роли объявлены в `:root` слоя `style` и там же вычисляются; потомки
наследуют готовое значение. Переопределение `--density` или `--brand-9` на контейнере не
пересчитывает `--space-*` и `--brand-solid` — половина ручек стенда «ничего не делала» именно
поэтому.

### 10. Браузерная обводка внутри списка снимается сознательно

Клавиатурный фокус внутри `select-listbox` ведёт kobalte: он переносит его между пунктами и
помечает текущий `data-highlighted`. Дефолтная обводка рисовалась поверх нашей подсветки тонкой
тёмной рамкой мимо палитры. Кольцо фокуса на кнопке-триггере при этом остаётся — его не трогаем.

### 11. Слои — только из шкалы `--z-*`

`z-index: 40` вместо `var(--z-dialog)` прошёл мимо всех проб, пока не появилась отдельная. Число
из головы спорит с чужими числами, и порядок панелей рушится там, где встретятся два слоя от
разных авторов.

### 12. Служебные координаты требуют `position` от оформления

Кит считает положение сам и пишет его инлайном — но `position` не ставит: это вид. Заливка
ползунка получала `left: 0%; right: 60%` и растягивалась на всю дорожку, потому что без
`position: absolute` краевые свойства не действуют. Выглядело как «ползунок всегда на сотне».

**Что делать:** там, где кит пишет координаты (заливка, бегунок, подвижная полоска), оформление
обязано дать систему координат — `position` на самой части и позиционированный предок.

**И обратное:** если позиционированного предка дать НЕЛЬЗЯ, потому что у обёртки нет зацепки —
это дефект контракта, а не повод ставить `position` наугад. Подвижная полоска сегментированного
выбора считается от обёртки, зацепки у обёртки нет, и полоска съезжает; правила оставлены
готовыми, а киту отправлена заявка. До неё выбор обозначается фоном сегмента.

### 13. Дев-сервер не видит выпуск соседней зоны

Vite не следит за `node_modules`. Сервер, поднятый до выпуска `ui` или `style`, продолжает
отдавать их прежнюю версию — и чинишь несуществующее. Проверять надо **время старта процесса**
(`ps -eo lstart`), а не доступность порта: `curl` отвечает 200 и от старого.

**Второй способ того же обмана:** после переоптимизации зависимостей (в логе — строка
`dependency optimized: …`) дев-сервер перестал применять solid-плагин и начал отдавать `.tsx` с
JSX как есть. В браузере это `SyntaxError: Unexpected token '<'` и пустая страница, в логе —
`Failed to parse source for import analysis`. Код зоны при этом цел: `pnpm lint` и `pnpm test`
зелёные. Лечится перезапуском с чисткой `node_modules/.vite`.

## Пробы

```bash
pnpm test        # 589 проб
pnpm lint        # eslint (канон Solid) + tsc
pnpm dev         # стенд на 5174; виден пультом tools/dev-nav
```

Что стерегут, кроме очевидного:

- **обе темы дают разный вид** — по каждому файлу проверяется, что он читает токен, значения
  которого в парах различаются; проход идёт по той же цепочке, что у браузера (роль → ступень →
  значение темы);
- **кит без `skin` остаётся голым** — по исходникам кита и по нашим модулям;
- **полнота семейства** — объявленное одетым обязано быть одето целиком, иначе у примитива одета
  рамка и гола галочка;
- **применение к узлу** — CSS вставляется в документ, рядом создаётся узел с `data-slot`, стиль
  спрашивается у движка. Границы среды названы в файле пробы: jsdom не понимает `@layer` и не
  резолвит `var()`.
- **что видит человек при мёртвой службе** — состояние ручек, а не провод: перечень пуст, вид не
  подключён, причина названа с адресом, стенд жив. Отдельно — что «служба ответила пустым» и
  «службы нет» не сливаются в одно: лечатся они разным.

Долг одевания печатается прогоном: сколько зацепок выпущено китом и ещё не одето.

Замеры стенда (разговор со службой пресетов — единственное, что здесь может встать):

```js
globalThis.__PROBE_WEB_SKIN_TRACE__ = true;
```

## Чего в зоне нет

Своего набора иконок · вариантов у остальных примитивов (пока только у кнопки) · шкалы ширин
поверхностей (четыре значения держатся в реестре пробы, заявка в `style`).

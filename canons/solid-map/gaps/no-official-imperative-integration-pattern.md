# Пробел: Solid не нормирует паттерн интеграции императивной библиотеки (и границу нереактивного)

**Вопросы (заказ M1, вопросы 5 и 8):** где проходит граница нереактивного канваса карты, и есть ли у Solid официальный предписанный паттерн работы с императивными библиотеками — или только практика обёрток?

**Ответ: официального паттерна нет.** Solid даёт примитивы (`ref`, `onMount`, `onCleanup`, `createEffect`), из которых мостик к императивному движку собирается, но НЕ публикует предписанного паттерна «как интегрировать imperative-библиотеку» и не описывает границу нереактивного канваса как норму.

## Что есть вместо паттерна — вычитанная из примитивов практика

Складывается устойчивый, но нигде не сформулированный как единое предписание рецепт (каждый примитив выписан в `sources/`):

| шаг | примитив | выписка |
|---|---|---|
| контейнер под канвас | `ref` на `<div>` | `solid-onmount-oncleanup` |
| создать экземпляр движка (рефы готовы, раз, только клиент) | `onMount` | `solid-onmount-oncleanup` |
| толкать состояние В движок при изменении сигналов | `createEffect` + API движка | `solid-createeffect` |
| снять экземпляр и обработчики | `onCleanup` | `solid-onmount-oncleanup` |
| не исполнять движок на сервере | `clientOnly` | `solidstart-clientonly` |

## Граница нереактивного (Q5) — следствие, не норма

Канвас/WebGL движка карты живёт ВНЕ DOM-реконсиляции Solid: Solid не рендерит его содержимое и не должен пытаться. Отсюда практический, но недокументированный как норма вывод: **внутрь контейнера карты Solid-разметку не кладут; всё, что рисует движок, меняется императивным вызовом его API из эффекта, а не реактивным рендером.** Ни одна страница доки Solid не формулирует эту границу прямо — она выводится из того, что `onMount`/`ref` отдают контейнер, а дальше владеет движок.

## Почему это пробел, а не недосмотр

Solid — набор реактивных примитивов, а не платформа с предписанным способом женить реактивность и императивность. Официального «паттерна интеграции imperative-библиотек» (аналога React-овских рекомендаций про `useRef`+`useEffect` как явно названного приёма) в доке Solid не поднято; явного отказа иметь мнение — тоже нет.

**Следствие для рамки:** рецепт интеграции карты придётся держать своим — он собирается из примитивов Solid (все первично выписаны), но опереться на единое предписание Solid «делай так» нельзя, его нет.

## Не закрыто (добор)

- `isServer` из `solid-js/web` для точечных серверных веток (не весь компонент).
- Обратное направление событий движка → сигналы (Q6): механика снятия обработчиков есть (`onCleanup`), но дословного предписания «события в сигналы» у Solid нет — вероятно, тоже практика.

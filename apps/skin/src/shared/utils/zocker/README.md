# Zocker

Общий вход к [`zocker`](https://www.npmjs.com/package/zocker) для всей витрины — строит валидный
экземпляр по Zod-схеме компонента (`entity/io.ts`), не по слепому подбору.

## Зачем

- **Схема → валидные данные, одним вызовом.** `zocker(schema).generate()` обходит Zod-схему сам —
  объекты, массивы, `enum`, юнионы, `record`/`map`/`set`, `z.lazy()`, regex-констрейнты — и
  гарантированно проходит `schema.safeParse`. Раньше это делал свой обходчик (`packages/io`'s
  `exampleOf`, снят) — `zocker` закрывает ту же задачу полнее.
- **Семантика по имени поля — из коробки.** Внутри `zocker` уже вшит `@faker-js/faker`: поле
  `id` получает UUID, `email` — настоящий email, `title`/`name`/`city` и десяток похожих —
  подходящий по смыслу faker-генератор, не случайный текст. Свой faker или обёртку над ним
  заводить не нужно — он уже часть `zocker`, не отдельная зависимость продукта.
- **Один путь импорта.** Тянуть пакет напрямую в каждой сущности незачем — если библиотека
  когда-нибудь сменится, менять путь придётся в одном месте, не в каждом файле, который строит
  примеры.

## Использование

```ts
import { zocker } from "#/shared/utils/zocker/index.js";

const example = zocker(schema).generate();
```

Сид, число записей, точечные `.supply()`/`.override()` — решает вызывающий на месте, файл
никакой политики не диктует.

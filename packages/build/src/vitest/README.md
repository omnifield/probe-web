# 🧪 vitest

📦 `@omnifield/probe-web-build/vitest`

Пресет тест-раннера для Solid-компонентов probe-web. `vitest.config.ts` потребителя едет
классом `placed-once` — кладут один раз и больше не трогают, — поэтому в нём остаются три
строки, а содержимое живёт здесь и меняется выпуском зоны.

```ts
// vitest.config.ts потребителя
import { defineTestConfig } from "@omnifield/probe-web-build/vitest";
export default defineTestConfig();
```

<h2 id="что-делает">🎯 Что делает</h2>

Три вещи, без которых тест Solid-компонента не работает, и все три — норма доки, а не
предпочтение (фонд `solidJS/sources/solid-docs-testing.md`, сверено 2026-08-08):

| поле | значение |
| ---- | -------- |
| `plugins: [solid()]` | JSX-трансформ в раннере |
| `resolve.conditions: ["development", "browser"]` | иначе `solid-js/web` разрешится в серверную ветку — см. «Почему conditions обязателен» |
| `test.environment: "jsdom"` | без документа рендерить некуда; `jsdom` — необязательный peer, нужен ровно тем, кто зовёт этот пресет |

Четвёртая вещь — следствие второй, и без неё пресет неполон: `test.server.deps.inline` — см.
«Почему deps.inline» ниже.

`@testing-library/jest-dom` пресет не подключает: `vite-plugin-solid` подхватывает его сам,
если он установлен (та же дока).

<h2 id="почему-conditions">🔀 Почему conditions обязателен</h2>

Без `resolve.conditions` падают два разных случая сразу:

- `solid-js/web` резолвится в серверную ветку, и `render()` падает «Client-only API called on
  the server side»;
- условие `solid` перестаёт дотягиваться до зависимостей — а именно им отдают НЕПРЕОБРАЗОВАННЫЙ
  JSX `@kobalte/core`, `@corvu/utils`, `solid-presence`, `solid-prevent-scroll` и собственный
  кит `-ui`.

<h2 id="deps-inline">📦 Почему deps.inline — по расширению</h2>

Условие `solid` означает «отдай мне исходник» — библиотека кладёт в свой `dist` файлы `.jsx` с
неразобранной разметкой. Раннер зависимость по умолчанию ВНЕШНИТ — отдаёт ноде нетронутой
(`server.deps.external`, дока vitest, сверено 2026-08-18). У ноды загрузчика для `.jsx` нет, и
проба на компонент падает `Unknown file extension ".jsx"` — на файле зависимости, а не на своём
коде, поэтому текст ошибки ведёт совсем не туда (заявка мира `PROBEWEB-37`).

Правило в пресете — по РАСШИРЕНИЮ файла, а не списком имён пакетов: расширение — свойство
самого файла («нода это исполнить не умеет»), а список имён пришлось бы дописывать на каждой
новой транзитивной зависимости кита, и он молча отстаёт. Правило может только превратить отказ
в успех: файл с таким расширением нода не исполнит ни при каких условиях, значит внешнить его
всегда неверно.

**Дефект выглядит выборочным** — почему у одних потребителей проба падает, а у других нет, см.
`FAQ.md`.

<h2 id="использование">🚀 Использование</h2>

```ts
// vitest.config.ts
import { defineTestConfig } from "@omnifield/probe-web-build/vitest";
export default defineTestConfig();
```

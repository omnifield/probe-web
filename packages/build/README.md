# 🛠️ probe-web build

📦 `@omnifield/probe-web-build`

Оснастка сборки probe-web: фабрика конфига Vite (приложение и библиотека), базовая настройка
TypeScript, пресет vitest и TS-раннер для серверов. Четыре темы наружу — и ни строки
рантайм-кода в самом приложении/сервере потребителя.

Зона отделена от `runtime` не ради симметрии: build-инструмент в зависимостях рантайма — это
названный дефект (`PROBEWEB-4`), и здесь он вычищен с обратной стороны — рантайм-кода в пакете
нет, а значит приложение не тащит сборщик в бандл.

<h2 id="структура">📁 Структура</h2>

Каждая тема — папка `src/<тема>/` с одинаковым скелетом: код (или конфиг-JSON, если темы это
касается) плюс `README.md`+`FAQ.md`+`ROADMAP.yaml`. `shared/` — исключение: инфраструктура, не
тема, своей триады не несёт, только `README.md`.

```
src/
├─ shared/              🧷 общее — perf-трейсы, общая база tsconfig
│  ├─ trace.ts
│  ├─ tsconfig.json
│  └─ README.md
├─ vite/                ⚡ /vite — конфиг приложения и библиотеки
│  ├─ index.ts
│  ├─ workspace-source.ts
│  ├─ README.md · FAQ.md · ROADMAP.yaml
├─ vitest/              🧪 /vitest — пресет тест-раннера
│  ├─ index.ts
│  └─ README.md · FAQ.md · ROADMAP.yaml
├─ tsconfig/            📐 /tsconfig — фронтенд-профиль типов
│  ├─ base.json
│  └─ README.md · FAQ.md · ROADMAP.yaml
└─ node/                🖥️ /tsconfig-node + probe-web-node — сервер без Vite
   ├─ base.json
   ├─ bin.mjs
   └─ README.md · FAQ.md · ROADMAP.yaml
```

В тарбол (`files` манифеста) едут только `dist` (код) и JSON-конфиги тем — `README.md`/
`FAQ.md`/`ROADMAP.yaml` каждой темы репозиторные, потребителю из реестра не нужны.

<h2 id="зачем-прятать">🔖 Зачем прятать конфиги</h2>

Файлы `vite.config.ts`, `tsconfig.json` и `vitest.config.ts` едут потребителю классом
**`placed-once`**: кладут один раз и больше никогда не обновляют. Всё, что окажется внутри,
застынет у него навсегда — версия Vite, набор плагинов, условия разрешения, `jsxImportSource`.
Поэтому у потребителя остаются три строки, а содержимое живёт в темах этой зоны и меняется
общим выпуском.

Каждая тема — часть замороженной поверхности выпуска (`PROBEWEB-4`, `PWEB-node`): менять её
нельзя без мажора и разговора с architect.

<h2 id="зависимости">📦 Зависимости</h2>

`vite-plugin-solid` и `tsx` — обычные зависимости: без первого не собрать `/vite`-конфиг, без
второго не работает `probe-web-node`, и потребитель ни про то, ни про другое знать не должен —
версия обоих решается здесь, а не у потребителя (`tsx` доезжает до серверного потребителя через
`pnpm`-симлинк `bin`, не как его собственная зависимость).

`vite` и `solid-js` — peer'ы (две копии Solid в дереве ломают реактивность). `vitest` и `jsdom`
— **необязательные** peer'ы: нужны ровно тем, кто зовёт `/vitest`.

<h2 id="трейсы">🩺 Трейсы</h2>

Perf-логгеры (`src/shared/trace.ts`) молчат по умолчанию; включает глобальный флаг:

```js
globalThis.__PROBE_WEB_BUILD_TRACE__ = true;
```

<h2 id="команды">▶️ Команды</h2>

```bash
pnpm run build      # tsc → dist
pnpm run typecheck  # проверка типов пакета
pnpm test           # vitest run
```

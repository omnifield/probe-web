## ✅ Что сделано в этой сессии

Три блока подряд:

1. **`entities/chat/ui/chat` разбит на компоненты.** `control/index.tsx` — форма (инпут+кнопка
   одним файлом), `content/item.tsx` — одно сообщение, `content/container.tsx` — скролл+`For`,
   `chat/index.tsx` — тонкая сборка. По ходу решением user из `ChatItem` убраны имя автора и время
   — в бабле остался только текст, аватар держит выравнивание своё/чужое.

2. **Зодер выпилен из витрины целиком.** `entities/component/utils/fake-generator/`,
   неиспользуемый `shared/utils/zocker/`, зависимость `zocker` в `package.json`/лок-файле, кнопка
   "GENERATE FAKE DATA" и авто-генерация в `Input`, fallback на `generate()` в
   `pages/embed/index.tsx` — всё удалено. Прямое решение user: наполнение — только из наших
   presets. `apps/skin/.mcp` не трогали — там своя, отдельная зависимость на zocker (другой
   пакет).

   Следом найден и починен баг: `Select` в `Input` был неконтролируемым и не реагировал на смену
   компонента в дереве (подпись на триггере залипала от предыдущего). Теперь контролируемый
   (`value={selected()}`), эффект на `items()` сам ставит пункт `0` по умолчанию или, если для
   компонента нет ни одной сохранённой записи, сбрасывает выбор и шлёт мок-строку `"-мок-"`.

3. **Чат подключён к реальной сессии агента.** Контракт назвал user: `POST
   /sessions/{id}/messages`, `Authorization: Bearer <общий токен>`, `X-User-Login: <логин>`, тело
   `{text, context: {component, variant, outfit}}`; ответ — один синхронный JSON
   (`event: "run-finished"`, `reply`/`refusal`/`did`), без стрима/поллинга. Перед реализацией
   уточнено четырьмя вопросами (см. лог ниже) — самое важное: **session id = имя ТЕКУЩЕГО
   компонента**, не отдельная сущность (агент хранит чат per-session, сессия должна быть в рамках
   компонента).

   Новый `entities/chat/model/api.ts`'s `sendChatMessage`; `store.ts`'s `sendMessage` стал
   асинхронным, завёл сигнал `pending` (форма дизейблится на время запроса). Моковая затравка
   сообщений убрана — история пуста, пока не будет реальной переписки.

## 📋 Открытые вопросы — не мои решения, спросить user/architect

- **`variant`/`outfit` в `context` чата не шлются вовсе** — их сейчас нигде во фронте нет (только
  `component` из роутинга и `tag`). Появится способ их выбирать (UI варианта/наряда) — `context` в
  `api.ts` надо расширить.
- **Токен `VITE_CHAT_TOKEN` не назван и не задан.** Без него запрос уйдёт без `Authorization` —
  зависит, требует ли сервис заголовок строго или можно без него на дев-стенде.
- **Базовый адрес чата (`VITE_CHAT_URL`)** — дефолт в коде `https://150.251.145.87/api`, назван
  user как временный. Сменится адрес — поправить дефолт или задать env при сборке/деплое.
- **История чата не грузится при заходе на компонент** — эндпоинт на это (`GET .../messages`?) не
  называли, `messages` стартует пустым каждый раз.
- **`did` (список вызовов MCP-тулов из ответа) нигде не рендерится** — типы в `api.ts` его несут
  (`ChatRunResult.did`), UI сейчас показывает только `reply`/`refusal`.

# @omnifield/probe-web-skin-reference

**Эталонный вид фреймворка** — три настоящие записи (палитра, формы, наряд), проходящие механику
скина целиком.

```ts
import { referenceOutfit, referencePalette, referenceForms } from "@omnifield/probe-web-skin-reference";
import { assemble, generateSkinCss } from "@omnifield/probe-web-skin";
import { passportOf } from "@omnifield/probe-web-ui/passport";

const { skin, report } = assemble(
  referenceOutfit,
  { palettes: [referencePalette], forms: referenceForms },
  passportOf,
);
const css = generateSkinCss(skin, passportOf);
```

## Три записи, а не одна

Компоненты приходят от разных поставщиков, и одна запись на всё требовала бы человека, который
опишет вид всех компонентов сразу. **Палитра** даёт значения ролей, **формы** решают, где роль
легла, **наряд** связывает их именами; складывает сборка, при надевании.

Роли названы по назначению: `акцент`, а не `синий`. Пересеяли палитру — имя роли осталось правдой,
а вид поменялся весь.

**Точечных правок в эталонном наряде НЕТ, и это ответ, а не пропуск.** Правка — признание, что
палитра компоненту не подошла; у эталона все пятеро одеты одной палитрой, и счёт правок,
отдаваемый механикой, равен нулю. Заводить исключение ради демонстрации механизма значило бы
соврать про сам эталон — механизм проверяется своим нарядом в пробе.

## Это ЗАПИСИ, а не лист

Наружу едут три записи. Ни строки CSS, ни готового файла стилей:
текст порождает механика, у потребителя и в тот момент, когда он его попросит. Отгрузи мы лист —
фреймворк снова начал бы одевать сбоку, просто под новым именем. Гейт поставки это проверяет: `.css`
в тарболе нет ни одного.

## Почему отдельная поставка

**Механика не знает ни одного скина.** Положи эталон внутрь неё — она перестала бы быть механикой и
стала бы механикой-с-видом, а «нет скина — нет визуала» держалось бы на честном слове.

Отдельный пакет делает это свойством **устройства**, а не договорённости: не установил — не
получил. Умолчание сбоку тут невозможно, а не «не предусмотрено».

Зависимость односторонняя: эталон знает механику и кит, механика о нём не знает ничего — это
отдельная проба, а не порядок слов. В собранном файле **ни одного импорта**: типы записей приходят
`import type` и стираются при эмите, поэтому поставка — чистые данные, а механику и кит потребитель
приносит сам одноранговыми.

## Это НЕ умолчание и НЕ первый скин продукта

Ни одна зона не начинает надевать эталон сама. Первый скин продукта и витрина принадлежат
архитектору скина; эталон существует ради трёх вещей:

1. **доказать, что механика работает целиком** — до него она проверялась по частям и на фикстурах;
2. **дать дом рядам, ушедшим из общего листа** — длительности, кривые, межстрочные, начертания сняты
   из базы как выбранный вкус, а вкус, отгруженный фреймворком, законен ровно в одном виде: скином;
3. **быть своим материалом** для гейта совпадения редактора с приложением — на чужом продуктовом
   скине наша готовность зависела бы от чужих сроков.

## Что внутри

**Палитра — семенами, обе половины.** Пять цветных шкал (`акцент`, `нейтраль`, `опасность`,
`успех`, `предупреждение`), каждая названа одним значением; ступени и обе половины строит та же
механика, что строит их для набора значений. Контраст обещан **построением**, а не подобран.

**Пять шкал при трёх употреблённых** — законно и намеренно: палитра закрывает словарь, а не
перечень использованного здесь. Из пяти одетых компонентов кита ни один состояния «успех» не
объявляет, а заводить вариацию «успешная кнопка» ради демонстрации значило бы придумать
продуктовый вкус в эталоне механики.

Имена ролей-шкал приходят из словаря механики и говорят, что шкала ЗНАЧИТ: вид пересеваем, и имя
`синий` соврало бы на первой же пересадке.

**Размерные семена** — все восемь, значениями прежнего листа. Плотность названа обязательно: без неё
каждая плотная ступень ссылалась бы на необъявленное имя, и браузер выбрасывал бы ступень целиком.

**Два семени объявлены полюсами** (`PWEB-80`) — интервалы и кегль: именно от них на узком экране
тесно и мелко. Скругление, толщина границы и трекинг с шириной окна не связаны ничем, и текучесть
добавила бы им движения без причины. Рукописного `clamp` в палитре нет: выражение печатает механика
из полюсов.

**Ряды без семени** — длительности, кривые, межстрочные, начертания — литералами: посеять их нечем,
значит это не шкала. Значения те же, что подставлял лист: эталон не повод менять их заодно.

**Формы на пятерых**, у кого есть паспорт: кнопка, гармошка, поверхность, поток, сетка. По одной на
компонент — эталон доказывает механику, а не показывает ассортимент.

### Чего здесь нет намеренно

| что | почему |
|---|---|
| `--control-target-min` | не вкус, а **порог нормы** (WCAG 2.2, 2.5.8). Объяви его скин — скин смог бы его «поправить». Высота контрола берётся ступенью `--control-height-md`, а она при плотности 1 выше порога с запасом |
| шкала слоёв (`--z-*`) | контракт сосуществования компонентов, а не вид: скин, поменявший порядок, ломает работу. Из одетых пятерых в слоях не живёт никто |
| тени | в тёмной половине подъём даётся светлотой, а не тенью, и из цветового семени тень не выводится — это названо перечнем `NOT_SEEDED` у механики |

## Два решения автора

### Покрытие — ПОЛНОЕ

Каждая объявленная часть и каждое объявленное состояние всех пятерых адресованы. `skinGaps`
отвечает пустым перечнем, и это проверяется машиной.

Скин вправе одевать часть кита — неодетое это долг, а не поломка. Но эталон существует ради
доказательства, что механика работает целиком, а непокрытая координата в нём — не скромность, а
координата, на которой механика **не проверена**: адрес не порождён, каскад не сложен, читаемость не
посчитана.

Цена названа: покрывать пришлось и то, что человек одевал бы не сразу. Правила там намеренно
скромные — их предмет «координата адресуема», а не «так красивее».

### Вариаций — три, две и ни одной

| компонент | вариаций | зачем столько |
|---|---|---|
| кнопка | 3 + умолчание | несёт ось целиком: умолчание и пересечение по **нескольким** вариациям сразу. С двумя пересечение выродилось бы в «по одной» |
| поверхность | 2 + умолчание | второй носитель оси, нарочно с другим числом: одинаковое число у всех читалось бы как требование |
| гармошка, поток, сетка | 0 | объявленная в паспорте ось скина **ни к чему не обязывает** — это стоит показать |

Больше имён эталон не заводит: вкус — предмет продуктового скина, а лишнее имя здесь читалось бы как
рекомендованный набор.

## Читаемость: что посчитано и что нет

Ни одной пары ниже нормы и ни одной неотличимой рамки против собственной заливки — ни в светлой
половине, ни в тёмной.

**Непосчитанное названо, и это один класс:** намеренно невидимая рамка сплошной кнопки
(`border-color: transparent`). Она держит коробку того же размера, что у обведённой вариации, и
«что лежит под полностью прозрачным» значение действительно не говорит — ответ «посчитать нечем»
здесь верный, а не пробел.

Отдельно механика объявляет своё непокрытое: контраст рамки против того, что лежит **снаружи** узла,
счётом не берётся — снаружи знает дерево, а скин от дерева независим. Эталон это не прячет.

## Гейт совпадения: редактор равен приложению

Шестой пункт потока — критерий приёмки всего продукта: человек собрал вид в редакторе и обязан
увидеть в приложении **то же самое**. `test/agreement.test.ts` превращает его в проверку.

Дорог к виду две, и они не одинаковые по устройству:

```
запись скина
  ├─ РЕДАКТОР:   порождение → ВЛОЖЕННАЯ форма → живой лист, на каждое движение ручки
  └─ ПРИЛОЖЕНИЕ: оборот через хранилище → порождение → ПЛОСКАЯ форма → лист → надет
```

Развести их молча может каждое из трёх различий: две формы вывода; оборот записи через JSON
(потерянное поле, съехавший порядок ключей, значение, которого JSON не знает); порядок правил в
каскаде. Оборот в пробе **настоящий** — `JSON.parse(JSON.stringify(...))`, а не передача ссылки:
передай мы ссылку, проверялось бы не то.

**Живым браузером, и это не роскошь.** Скин живёт в каскадном слое, а `jsdom` слои игнорирует
целиком — не упорядочивает, а выбрасывает. Сравнить результат двух дорог он не может в принципе:
обе покажутся пустыми, и проба будет зелёной оттого, что сравнивать нечего. Текстовая сверка —
другой вопрос: формы законно различаются написанием, а предмет здесь вычисленный вид.

**Цена названа:** прогон поднимает настоящий Chromium и дороже обычной пробы. Оправдана ровно
тем, что иначе главное обещание продукта непроверяемо (граница — в README `@omnifield/live-check`).

**На обеих дорогах теперь стоит СБОРКА** (`PWEB-78`): совпадать обязан собранный вид, а не
порождение одной записи. Оборот через хранилище проходят все три записи — наряд ссылается именами,
и потеря имени формы обязана дать отказ сборки, а не тихо иной вид.

Сравниваются шесть узлов, адресованных координатами **настоящих** паспортов: умолчание, вариация,
состояние принудительным признаком, состояние атрибутом, вариация поверхности и содержимое
раскрытого раздела — вид по состоянию **предка**. Обе половины проверяются отдельно: расхождение
может жить в одной.

Три контроля стоят рядом с предметом и постоянно: замер не пуст (узлы найдены и одеты); половины
между собой различаются (иначе совпадение ничего не значило бы); испорченная дорога приложения
расходится с редакторской.

## Разработка

```bash
pnpm run build      # esbuild → dist/index.js, затем tsc → декларации
pnpm run lint       # eslint + typecheck
pnpm run test       # build + vitest
```

Машинного pre-commit в репозитории нет: сборку, типы и пробы гоняем руками перед каждым коммитом.

**Форму обвязки отдаёт её владелец.** Свою копию мы держали недолго и держали названным пробелом:
`@omnifield/live-check` деклараций не отдавал, а молчаливый `any` довёз бы опечатку в имени функции
до прогона браузера, где она выглядела бы как поломка замера. Пробел закрыт в зоне-владельце, копия
снята. Довод тот же, по которому её и назвали пробелом: потребитель объявляет форму по тому, чем
пользуется сам, и на правке обвязки его файл остался бы верным по типам и неверным по делу.

Протокол при этом намеренно не типизирован и у владельца: `call` принимает метод строкой и отдаёт
разбор `unknown`. Расписать протокол значило бы завести вторую копию чужой спецификации, которая
устареет на первом же обновлении браузера — приводит ответ тот, кто знает, что спросил.

**Мутационные проверки** — каждая прогонялась.

| что ломаем | что обязано покраснеть |
|---|---|
| выписать лестницу шкалы литералами вместо семени | `reference.test.ts` — «ни один цвет не выписан литералом» и «пересев меняет весь вид» |
| снять рецепт компонента | `coverage.test.ts` — покрытие; там же стоит и положительный контроль на слепоту счёта |
| написать правило против назначения ступени (текст 11-й на 9-ю) | `coverage.test.ts` — «ни одной пары ниже нормы» |
| завести обычную зависимость в манифесте | `surface.test.ts` — «в поставке ни одного импорта»; `pack.test.ts` — «не привозит с собой ничего» |
| упомянуть эталон в механике | `surface.test.ts` — направление зависимости |
| положить `.css` в поставку | `pack.test.ts` — «эталон это запись, а не лист» |
| сравнить одну дорогу с собой (`дорогаПриложения = дорогаРедактора`) | `agreement.test.ts` — «дороги действительно две» |
| сборка берёт палитру не по имени наряда | `reference.test.ts` — «пересев меняет весь вид» |
| точечная правка печатается на `:root` вместо координаты компонента | `agreement.test.ts` — «не действует за его границами», живым браузером |
| убрать роль-шкалу из перечня механики | `reference.test.ts` — сборка отказывает: палитра задаёт шкалу вне словаря |
| перевернуть знак наклона в печати текучего выражения | `agreement.test.ts` — «значение при узком и широком окне разное», живым браузером |
| убрать посадку на сетку | `agreement.test.ts` — «на обеих ширинах сидит на сетке»: узкое окно даёт `24.3232px` |
| испортить дорогу приложения (подменить значение в плоской форме) | `agreement.test.ts` — «светлая: редактор и приложение дают один вид» |

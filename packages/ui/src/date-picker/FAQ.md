# ❓ FAQ

Короткие ответы на конкретные вопросы, которые уже возникали по этому компоненту. Не общая
документация (она в [`README.md`](./README.md)) и не план (он в [`ROADMAP.yaml`](./ROADMAP.yaml))
— только факты, каждый проверен на практике.

---

### Почему `tableCellTrigger` несёт двадцать состояний — не многовато ли для одной ячейки календаря?

**Коротко: это не раздутость, а честный список того, что реально умеет одна ячейка — от вида сетки до превью наведения при выборе диапазона.**

Три значения `view` (день/месяц/год — одна и та же часть служит всем трём сеткам), восемь общих
состояний для любого вида, три состояния только-дневного-вида (`today`/`unavailable`/`weekend`),
три состояния превью наведения при выборе диапазона (реальные, но истинные только в режиме
`range`) и три обычных псевдокласса кнопки — вместе двадцать. Каждое отражает настоящий, отдельно
проверяемый факт компонента-первоисточника, не выдумано для симметрии с другими частями кита.

### Почему `tableCell`'s `selected` работает по-разному в дневном виде и в видах месяца/года?

**Коротко: реальная непоследовательность компонента-первоисточника, а не недосмотр здесь.**

В дневном виде выбранная ячейка получает `aria-selected`, но никогда `data-selected` — атрибут
данных на этом уровне коннектор просто не ставит. В видах месяца и года — наоборот, обе версии
получают `data-selected` вдобавок к `aria-selected`. Паспорт объявляет `selected` один раз на общей
части `tableCell` (она обслуживает все три вида), а не скрывает разницу между видами — если понадобится
стилизовать выбор дня именно через `data-selected`, придётся идти через `tableCellTrigger`, где
`aria-selected` не единственный источник факта.

### Почему `DatePickerWeekNumberCell`/`DatePickerWeekNumberHeaderCell` экспортированы, но не входят в карту кита?

**Коротко: они не отдельная часть анатомии — оба делят координату `tableCell`, просто рисуют её по-другому.**

Карта кита (`components/index.ts`) требует ровно один компонент на каждую ЧАСТЬ паспорта. Номера
недели — не двадцать шестая часть, а третий способ нарисовать уже существующую `tableCell`: тот же
адрес (`data-part="table-cell"`), другая визуальная роль. Оба компонента реальны и по-прежнему
доступны прямым импортом (`showWeekNumbers` в README показывает как), просто их незачем и нельзя
включать в карту «часть → один компонент» — они не описывают новую часть, а предлагают альтернативу
уже описанной.

### Почему у пикера даты нет способа программно перейти к конкретной дате или узнать состояние машины снаружи?

**Коротко: `DatePickerContext`/`useDatePickerContext` — реальный, полноценный API компонента-первоисточника, но кит его нигде не реэкспортирует, тот же пробел, что у `carousel`.**

Компонент-первоисточник отдаёт весь императивный слой (переход к дате, управление фокусом внутри
сетки, очистка значения, доступ к текущему виду и выбору) через контекст, доступный вызовом
`useDatePickerContext()` внутри дерева `DatePicker`. Ни сам хук, ни `DatePickerContext`, ни
`useDatePicker` кит не реэкспортирует ни из одного файла — собрать, например, кнопку «перейти к
сегодняшней дате» снаружи стандартной композиции сейчас можно только импортируя это напрямую из
`@ark-ui/solid/date-picker`, в обход кита. Честно вынесено как пробел — `ROADMAP.yaml`.

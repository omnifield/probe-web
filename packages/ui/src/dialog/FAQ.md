# ❓ FAQ

Короткие ответы на конкретные вопросы, которые уже возникали по этому компоненту. Не общая
документация (она в [`README.md`](./README.md)) и не план (он в [`ROADMAP.yaml`](./ROADMAP.yaml))
— только факты, каждый проверен на практике.

---

### Почему у диалога нет части `root`, хотя у большинства компонентов кита она есть?

**Коротко: `Dialog` сам по себе не рисует DOM-узел — только контекст, номинальным корнем паспорт называет `positioner`.**

Та же схема, что у поповера и шторки: плавающие компоненты порталятся ближе к концу документа, и
самому «корню» физически нечего рисовать — он только раздаёт состояние вложенным частям через
контекст. Реального DOM-узла на этом уровне нет, поэтому и адреса ему кит не даёт: `passport.root`
называет `positioner` — первую часть, у которой этот узел реально есть.

### Почему `role="alertdialog"` — это не просто смена атрибута для скринридера?

**Коротко: вместе с ролью меняется реальное поведение — фокус по умолчанию и закрытие кликом снаружи.**

Компонент читает `role` не только для `aria-`атрибута на самом узле — при
`alertdialog` фокус по умолчанию уходит на кнопку закрытия/отмены (не на первый фокусируемый
элемент, как в обычном `dialog`), и клик снаружи диалог не закрывает. Оба поведения осмысленны для
предупреждения об опасном действии: пользователь не должен закрыть диалог случайным кликом мимо и
не должен по инерции попасть фокусом сразу на разрушительную кнопку.

### Почему потребителю не нужно самому оборачивать `DialogBackdrop`/`DialogPositioner` в `Portal`, хотя все примеры на ark-ui.com делают это явно?

**Коротко: кит портализует обе части сам, внутри своих компонентов — то же решение, что уже принято для `select`'s позиционера.**

На ark-ui.com каждый пример диалога вручную оборачивает `Dialog.Backdrop`+`Dialog.Positioner` в
свой собственный `<Portal>` — без этого разметка остаётся там, где написана в JSX, и на настоящей
странице более поздний несвязанный сосед может визуально перекрыть диалог или (хуже) незаметно
забрать себе клики поверх него — тот же класс бага, что уже был найден вживую и исправлен для
`select`'s позиционера. Кит закрывает это на своём уровне (`components/backdrop.tsx`,
`components/positioner.tsx` — каждый оборачивает себя в `Portal` из `solid-js/web`), чтобы
потребителю ни разу не пришлось вспоминать про портал самому.

### Почему клик по одному из нескольких `DialogTrigger` помечает именно его как `current`, хотя диалог один на всех?

**Коротко: `value` на каждом триггере — то же различение, что и у `drawer`/`popover` с несколькими триггерами.**

Машина хранит не «открыт/закрыт» само по себе, а ещё и то, какой конкретно триггер его открыл
(`triggerValue`) — `current` на `DialogTrigger` сравнивает его собственный `value` с этим
значением. Композиция ничем не отличается от обычного случая с одним триггером — просто их
несколько, и каждый называет себя.

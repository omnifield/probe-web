# Зона `skin` — готовые оформления для безголового кита

**Что здесь лежит:** правила вида для примитивов зоны `ui` (только CSS) и пресеты — наборы
значений вида, отчуждаемые от стенда.
Контракт зоны — `kb:PROBEWEB-11`, правила зон `products/` — `kb:PROBEWEB-5`.

```
src/skin/      поставка: base.css (объявление слоя) + по файлу на семейство + сборный skin.css
src/presets/   пресеты как данные: встроенные, модель, хранилище своих
src/playground/ стенд: витрина, кейсы, панель настройки скина
test/          пробы: зацепки, литералы, слои, темы, применение к узлу
```

## Как это подключается

```ts
import "@omnifield/probe-web-style/base.css";   // роли и производные шкалы
import "@omnifield/probe-web-style/themes.css"; // ступени палитры
import "@probe-web/skin/skin.css";              // весь кит одной строкой
```

Нужна только кнопка — берите `base.css` (он объявляет слой) и `button.css`. Раздельные подпути
существуют ровно для этого.

**Снимается удалением импорта.** Кит без нас — голые примитивы с зацепками `data-slot`, ровно
то, чем он и является. Это первое правило зоны, и его стережёт проба, а не обещание.

## Пресеты — вид одним указанием

**Пресет** — полный набор значений вида: семена шкал, правки тёмной пары, скругление, шаг
интервалов, базовый кегль, высота контрола, плотность. Подключается целиком, а не по одной вещи.

```ts
import "@probe-web/skin/presets/twitter.css";
```

```html
<html data-theme="twitter">   <!-- тёмная пара — классом dark, как у базовой темы -->
```

Всё. Ни сборки, ни строки JS: **CSS первичен**, потому что «взять этот вид» должно работать
указанием файла и атрибута. Описание объектом (`src/presets/`) — источник, из которого файл
рождается; потребителю нужен файл. Встроенных три: `twitter` (дефолт), `neutral` (точка отсчёта —
семена базы, ничего своего), `dense` (для пультов и таблиц, где важно число строк).

**Механика от пресета не меняется.** Что в пресет намеренно **не** входит:

- светлый/тёмный режим — выбор пользователя, один пресет обязан работать в обоих;
- варианты кнопок и прочая поверхность зоны — иначе пресет менял бы поведение, а не вид;
- подключено ли оформление вообще — это состояние стенда.

**Свой пресет** делается из любого встроенного: покрутили ручки на стенде — он стал изменённым, —
сохранили под своим именем, и он встал в список наравне со встроенными. У изменённого пресета
выдача CSS закрыта до сохранения: он выпускается под именем пресета, и правка встроенного
`dense` переписала бы `[data-theme="dense"]` у потребителя чужими значениями.

Генерация файлов — `pnpm run build:presets`. Сгенерированное лежит в репозитории и сверяется
пробой: расхождение файла с моделью — красный прогон с указанием перегенерировать.

## Три правила, которые нельзя нарушать

1. **Кит остаётся голым.** `skin` не правит `ui`. Зависимость односторонняя: мы знаем про кит,
   кит про нас — никогда. В поставке нет ни одного JS-модуля.
2. **Цепляемся за `data-slot`.** Имена классов и структура DOM — внутреннее дело кита; зацепки
   объявлены его обязательством (`packages/ui/test/slot-list.ts`).
3. **Ни одного значения литералом.** Цвета, скругления, длительности, размеры, слои — только
   токенами слоя `style`. Не хватает токена — заявка, а не литерал на месте.

## Варианты и размеры — публичная поверхность зоны

Кит безголовый и пропов вида не имеет. Вариант выбирает **потребитель атрибутом**, оформление
его читает:

```tsx
<Button>Сохранить</Button>                          {/* основное действие */}
<Button data-variant="outline">Отмена</Button>       {/* парное */}
<Button data-variant="danger" data-size="sm">Удалить</Button>
```

| `data-variant` | когда |
|---|---|
| нет атрибута | основное действие; простая разметка сразу даёт рабочий вид |
| `soft` | частое, но не главное действие |
| `outline` | парное действие рядом с основным |
| `ghost` | плотный ряд, где рамки создают шум |
| `danger` | необратимое действие |
| `danger-outline` | необратимое, но не главное |

`data-size`: `sm` · без атрибута (средний) · `lg`.

**Имя варианта — обещание.** Потребитель ставит его в разметку, и удаление имени ломает ему вид.
Перечень закрыт и стережётся пробой с двух сторон: объявленное обязано быть одето, одетое —
объявлено. Неизвестное значение атрибута кнопку не ломает: она остаётся в дефолтном виде.

Отдельная проба считает **контраст подписи на фоне для каждого варианта**, в обеих парах тем, и
пары читает из самого CSS, а не из списка рядом с проверкой. Иначе подмена роли в оформлении
прошла бы молча: проба продолжала бы проверять свой список.

## Ловушки одевания — каждая оплачена ошибкой

Это не свод хороших манер, а список того, на чём зона уже спотыкалась. Каждый пункт стоил
захода или правки после показа user.

### 1. Интерактивная область обязана совпадать с видимой

Триггер подсказки стоял в flex-колонке. Колонка растягивает детей по ширине — область наведения
вышла на всю панель, и подсказка всплывала от пустого места рядом с заголовком.

**Что делать:** любой элемент, у которого есть реакция на указатель или фокус (триггер, ссылка,
кнопка-иконка), внутри `flex`/`grid`-контейнера получает `inline-size: fit-content` и
`align-self`, либо задаётся не растягивающимся по природе. Проверка простая: границы наведения
должны быть там, где нарисовано.

### 2. Зацепка на узле бывает СПИСКОМ — точное равенство мимо неё

`<DialogTrigger as={Button}>` рендерит один узел, и на нём оба имени:
`data-slot="button dialog-trigger"`. Под `[data-slot="button"]` такой узел не попадает —
оформление кнопки просто не применяется, и ничего при этом не падает.

**Что делать:** читать зацепку списком — `[data-slot~="button"]`. Одиночному значению `~=` не
мешает, поэтому в поставке точного равенства нет ни одного, и это стережёт проба.

### 3. Повтор вида у зацепки-двойника ляжет ПОВЕРХ настоящей

Голый `<PopoverTrigger>Текст</PopoverTrigger>` тоже обязан выглядеть контролом, поэтому вид
кнопки у триггеров повторён — это цена независимых подпутей. Но у составного узла настоящий
вид кнопки уже есть, а файлы всплывающих идут после `button.css`: специфичность равная,
побеждает порядок, и `data-variant="danger"` тихо становится обычной кнопкой.

**Что делать:** исключать составной узел — `[data-slot~="popover-trigger"]:not([data-slot~="button"])`.
Реестр таких зацепок и проверка исключения — в `test/hooks.test.ts`.

### 4. Часть, требующая контекста пункта, вне пункта роняет kobalte

`DropdownMenuItemLabel` внутри `DropdownMenuSubTrigger` — открывашка подменю не является пунктом
меню. Ошибка приходит в консоль, а меню не открывается ВОВСЕ. Страница при этом жива, и по виду
кажется, что «просто ничего не происходит».

### 5. Форма несёт смысл, и её нельзя терять при смене темы

Флажок с крупным семенем скругления (у нашей палитры `1.3rem`) превращался в круг и становился
неотличим от варианта группы. Квадрат — «выбери сколько угодно», круг — «выбери одно».

**Что делать:** там, где форма различает поведение, ставить потолок:
`border-radius: min(var(--radius-xs), 0.35em)`.

### 6. Узел значка может быть НЕ пуст

kobalte кладёт в `select-icon` символ `▼` по умолчанию. Оформление чертило поверх него свой
шеврон границами — на экране складывались обе фигуры.

**Что делать:** значок ОФОРМЛЯТЬ (место, кегль, цвет, поворот), а не рисовать. Тогда и свой
значок потребителя получит те же правила.

### 7. Место и зазор всплывающих задаёт позиционировщик, а не оформление

`gutter`, `placement`, `shift`, `flip`, `sameWidth` — опции на КОРНЕ (`Select`, `Popover`,
`Tooltip`, `DropdownMenu`). Отступ в CSS спорит с floating-ui за ту же величину, которую тот
переписывает каждый кадр.

### 8. Семена настройки ставятся на КОРЕНЬ документа

Производные шкалы и роли объявлены в `:root` слоя `style` и там же вычисляются; потомки
наследуют готовое значение. Переопределение `--density` или `--brand-9` на контейнере не
пересчитывает `--space-*` и `--brand-solid` — половина ручек стенда «ничего не делала» именно
поэтому.

### 9. Браузерная обводка внутри списка снимается сознательно

Клавиатурный фокус внутри `select-listbox` ведёт kobalte: он переносит его между пунктами и
помечает текущий `data-highlighted`. Дефолтная обводка рисовалась поверх нашей подсветки тонкой
тёмной рамкой мимо палитры. Кольцо фокуса на кнопке-триггере при этом остаётся — его не трогаем.

### 10. Слои — только из шкалы `--z-*`

`z-index: 40` вместо `var(--z-dialog)` прошёл мимо всех проб, пока не появилась отдельная. Число
из головы спорит с чужими числами, и порядок панелей рушится там, где встретятся два слоя от
разных авторов.

### 11. Служебные координаты требуют `position` от оформления

Кит считает положение сам и пишет его инлайном — но `position` не ставит: это вид. Заливка
ползунка получала `left: 0%; right: 60%` и растягивалась на всю дорожку, потому что без
`position: absolute` краевые свойства не действуют. Выглядело как «ползунок всегда на сотне».

**Что делать:** там, где кит пишет координаты (заливка, бегунок, подвижная полоска), оформление
обязано дать систему координат — `position` на самой части и позиционированный предок.

**И обратное:** если позиционированного предка дать НЕЛЬЗЯ, потому что у обёртки нет зацепки —
это дефект контракта, а не повод ставить `position` наугад. Подвижная полоска сегментированного
выбора считается от обёртки, зацепки у обёртки нет, и полоска съезжает; правила оставлены
готовыми, а киту отправлена заявка. До неё выбор обозначается фоном сегмента.

### 12. Дев-сервер не видит выпуск соседней зоны

Vite не следит за `node_modules`. Сервер, поднятый до выпуска `ui` или `style`, продолжает
отдавать их прежнюю версию — и чинишь несуществующее. Проверять надо **время старта процесса**
(`ps -eo lstart`), а не доступность порта: `curl` отвечает 200 и от старого.

## Пробы

```bash
pnpm test        # 590 проб
pnpm lint        # eslint (канон Solid) + tsc
pnpm dev         # стенд на 5174; виден пультом tools/dev-nav
```

Что стерегут, кроме очевидного:

- **обе темы дают разный вид** — по каждому файлу проверяется, что он читает токен, значения
  которого в парах различаются; проход идёт по той же цепочке, что у браузера (роль → ступень →
  значение темы);
- **кит без `skin` остаётся голым** — по исходникам кита и по нашим модулям;
- **полнота семейства** — объявленное одетым обязано быть одето целиком, иначе у примитива одета
  рамка и гола галочка;
- **применение к узлу** — CSS вставляется в документ, рядом создаётся узел с `data-slot`, стиль
  спрашивается у движка. Границы среды названы в файле пробы: jsdom не понимает `@layer` и не
  резолвит `var()`.

Долг одевания печатается прогоном: сколько зацепок выпущено китом и ещё не одето.

## Чего в зоне нет

Своего набора иконок · вариантов у остальных примитивов (пока только у кнопки) · шкалы ширин
поверхностей (четыре значения держатся в реестре пробы, заявка в `style`).

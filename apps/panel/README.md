# `panel` — витрина продуктов web-core

**Одно место, откуда можно пройтись по продуктам.** Сейчас показывает только скин-редактор;
таблицы и остальные продукты подключаются позже тем же приёмом.

Едет в прод вместе со всем остальным (решение user 2026-08-26): пока репозиторий один, панель —
не дев-инструмент, а часть поставки, и написана соответственно — обычным Nx/Vite-приложением, без
самодельной оснастки.

## Чем это было раньше и почему снесено (`PWEB-124`)

До этой правки роль панели играл `tools/dev-nav` — самописный сервер на голом `node:http`,
дёргавший дочерние `vite`-процессы вручную сформированными байтами. У этого было три цены:

- **отдельный неуправляемый процесс.** Не находился Nx, не перезапускался вместе с остальным
  через `pnpm run dev` — поднимался и гасился руками, отдельной командой (`pnpm nav`);
- **протухающий кеш.** `node_modules/.vite` дочерних процессов не был связан с жизненным циклом
  дев-нава, и после переезда файлов между пакетами витрина показывала `404` на путях, которых
  давно не существует, пока кеш не почистишь руками;
- **самодельный роутинг вместо готового.** Прокси на «текущую» зону выбирался кукой и
  реализовывался вручную (`http.createServer`, ручной pipe байтов) — то есть заново писал то, что
  `vite`/`http-proxy` уже умеют.

Всё это снесено. `apps/panel` — три строки `vite.config.ts`, как у любого другого приложения в
репозитории (см. `apps/reference/vite.config.ts`, `apps/skin/vite.config.ts`), находится Nx
по тому же признаку (скрипт `dev` в `package.json`), поднимается той же командой из корня —
`pnpm run dev`.

## Как показан продукт — и почему БЕЗ прокси

`Panel` (`src/panel.tsx`) кладёт продукт в `<iframe>`, у которого `src` смотрит **прямо на порт
дев-сервера продукта** (`http://localhost:5174/` для скина), а не через саму панель.

Прокси через дев-сервер панели пробовали и отмерили живьём: та же витрина скина, открытая через
проксирующий хоп, грузилась заметно дольше прямого порта, а HMR-сокет скина через прокси не
доживал вовсе (упирался в собственный HMR-сокет панели на том же порту). Ограничения «наружу
торчит только один порт», ради которого проксирование вообще заводили, здесь тоже нет — порт
каждого продукта и так открыт напрямую. Значит и городить прокси незачем.

## Как добавить ещё один продукт

1. Дописать запись в `PRODUCTS` (`src/panel.tsx`) — `id`, подпись и `url` порта дев-сервера
   продукта.
2. Больше ничего: опроса живости и переключения между вкладками пока нет — они появятся, когда
   продуктов станет больше одного и реально понадобится решать, какой показывать (решение user:
   не заводить механику заранее).

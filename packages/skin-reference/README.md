# @omnifield/probe-web-skin-reference

**Эталонный скин фреймворка** — одна настоящая запись переменных и рецептов, проходящая механику
скина целиком.

```ts
import { referenceSkin } from "@omnifield/probe-web-skin-reference";
import { generateSkinCss } from "@omnifield/probe-web-skin";
import { passportOf } from "@omnifield/probe-web-ui/passport";

const css = generateSkinCss(referenceSkin, passportOf);
```

## Это ЗАПИСЬ, а не лист

Наружу едет `Skin` — переменные и рецепты одной единицей. Ни строки CSS, ни готового файла стилей:
текст порождает механика, у потребителя и в тот момент, когда он его попросит. Отгрузи мы лист —
фреймворк снова начал бы одевать сбоку, просто под новым именем. Гейт поставки это проверяет: `.css`
в тарболе нет ни одного.

## Почему отдельная поставка

**Механика не знает ни одного скина.** Положи эталон внутрь неё — она перестала бы быть механикой и
стала бы механикой-с-видом, а «нет скина — нет визуала» держалось бы на честном слове.

Отдельный пакет делает это свойством **устройства**, а не договорённости: не установил — не
получил. Умолчание сбоку тут невозможно, а не «не предусмотрено».

Зависимость односторонняя: эталон знает механику и кит, механика о нём не знает ничего — это
отдельная проба, а не порядок слов. В собранном файле **ни одного импорта**: тип `Skin` приходит
`import type` и стирается при эмите, поэтому поставка — чистые данные, а механику и кит потребитель
приносит сам одноранговыми.

## Это НЕ умолчание и НЕ первый скин продукта

Ни одна зона не начинает надевать эталон сама. Первый скин продукта и витрина принадлежат
архитектору скина; эталон существует ради трёх вещей:

1. **доказать, что механика работает целиком** — до него она проверялась по частям и на фикстурах;
2. **дать дом рядам, ушедшим из общего листа** — длительности, кривые, межстрочные, начертания сняты
   из базы как выбранный вкус, а вкус, отгруженный фреймворком, законен ровно в одном виде: скином;
3. **быть своим материалом** для гейта совпадения редактора с приложением — на чужом продуктовом
   скине наша готовность зависела бы от чужих сроков.

## Что внутри

**Переменные — семенами, обе половины.** Три цветные шкалы (`бренд`, `нейтраль`, `опасность`),
каждая названа одним значением; ступени и обе половины строит та же механика, что строит их для
набора значений. Контраст обещан **построением**, а не подобран.

Имена шкал говорят, что шкала ЗНАЧИТ, а не какого она цвета: скин пересеваем, и имя `синий` соврало
бы на первой же пересадке.

**Размерные семена** — все восемь, значениями прежнего листа. Плотность названа обязательно: без неё
каждая плотная ступень ссылалась бы на необъявленное имя, и браузер выбрасывал бы ступень целиком.

**Ряды без семени** — длительности, кривые, межстрочные, начертания — литералами: посеять их нечем,
значит это не шкала. Значения те же, что подставлял лист: эталон не повод менять их заодно.

**Рецепты на пятерых**, у кого есть паспорт: кнопка, гармошка, поверхность, поток, сетка.

### Чего здесь нет намеренно

| что | почему |
|---|---|
| `--control-target-min` | не вкус, а **порог нормы** (WCAG 2.2, 2.5.8). Объяви его скин — скин смог бы его «поправить». Высота контрола берётся ступенью `--control-height-md`, а она при плотности 1 выше порога с запасом |
| шкала слоёв (`--z-*`) | контракт сосуществования компонентов, а не вид: скин, поменявший порядок, ломает работу. Из одетых пятерых в слоях не живёт никто |
| тени | в тёмной половине подъём даётся светлотой, а не тенью, и из цветового семени тень не выводится — это названо перечнем `NOT_SEEDED` у механики |

## Два решения автора

### Покрытие — ПОЛНОЕ

Каждая объявленная часть и каждое объявленное состояние всех пятерых адресованы. `skinGaps`
отвечает пустым перечнем, и это проверяется машиной.

Скин вправе одевать часть кита — неодетое это долг, а не поломка. Но эталон существует ради
доказательства, что механика работает целиком, а непокрытая координата в нём — не скромность, а
координата, на которой механика **не проверена**: адрес не порождён, каскад не сложен, читаемость не
посчитана.

Цена названа: покрывать пришлось и то, что человек одевал бы не сразу. Правила там намеренно
скромные — их предмет «координата адресуема», а не «так красивее».

### Вариаций — три, две и ни одной

| компонент | вариаций | зачем столько |
|---|---|---|
| кнопка | 3 + умолчание | несёт ось целиком: умолчание и пересечение по **нескольким** вариациям сразу. С двумя пересечение выродилось бы в «по одной» |
| поверхность | 2 + умолчание | второй носитель оси, нарочно с другим числом: одинаковое число у всех читалось бы как требование |
| гармошка, поток, сетка | 0 | объявленная в паспорте ось скина **ни к чему не обязывает** — это стоит показать |

Больше имён эталон не заводит: вкус — предмет продуктового скина, а лишнее имя здесь читалось бы как
рекомендованный набор.

## Читаемость: что посчитано и что нет

Ни одной пары ниже нормы и ни одной неотличимой рамки против собственной заливки — ни в светлой
половине, ни в тёмной.

**Непосчитанное названо, и это один класс:** намеренно невидимая рамка сплошной кнопки
(`border-color: transparent`). Она держит коробку того же размера, что у обведённой вариации, и
«что лежит под полностью прозрачным» значение действительно не говорит — ответ «посчитать нечем»
здесь верный, а не пробел.

Отдельно механика объявляет своё непокрытое: контраст рамки против того, что лежит **снаружи** узла,
счётом не берётся — снаружи знает дерево, а скин от дерева независим. Эталон это не прячет.

## Разработка

```bash
pnpm run build      # esbuild → dist/index.js, затем tsc → декларации
pnpm run lint       # eslint + typecheck
pnpm run test       # build + vitest
```

Машинного pre-commit в репозитории нет: сборку, типы и пробы гоняем руками перед каждым коммитом.

**Мутационные проверки** — каждая прогонялась.

| что ломаем | что обязано покраснеть |
|---|---|
| выписать лестницу шкалы литералами вместо семени | `reference.test.ts` — «ни один цвет не выписан литералом» и «пересев меняет весь вид» |
| снять рецепт компонента | `coverage.test.ts` — покрытие; там же стоит и положительный контроль на слепоту счёта |
| написать правило против назначения ступени (текст 11-й на 9-ю) | `coverage.test.ts` — «ни одной пары ниже нормы» |
| завести обычную зависимость в манифесте | `surface.test.ts` — «в поставке ни одного импорта»; `pack.test.ts` — «не привозит с собой ничего» |
| упомянуть эталон в механике | `surface.test.ts` — направление зависимости |
| положить `.css` в поставку | `pack.test.ts` — «эталон это запись, а не лист» |

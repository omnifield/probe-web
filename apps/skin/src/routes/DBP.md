# `routes` — не отдельный слой FSD, а физическое расширение `app`

## Почему эта папка вообще существует отдельно

Канонический порядок слоёв FSD сверху вниз: `app → pages → widgets → features → entities →
shared`.
`routes` в этот список НЕ входит — это не бизнес-слой методологии, а техническое требование
файлового роутера (`TanStack Router`): он сканирует диск и строит дерево маршрутов из имён
файлов в отдельной директории (`_workspace.showcase.$component.tsx` и т.п.). Концептуально то,
что здесь лежит — часть `app`-слоя (композиция роутинга), просто физически вынесенная в свою
папку, потому что так работает генератор `routeTree.gen`.

Все файлы здесь — тонкие: `createFileRoute(...)`, импорт готовой страницы, минимум логики.

## Правило импортов

- `routes` импортирует из `pages` (`../pages/lab`, `../pages/showcase`...) и из
  роутер-пакета (`@tanstack/solid-router`, `@web-core/router`).
- НЕ импортирует `widgets`/`entities`/`shared` напрямую в обход `pages` — если маршруту нужен
  виджет или сущность, он должен прийти через страницу, которую этот маршрут монтирует, а не
  минуя её. Иначе смысл слоя `pages` как единой точки композиции экрана размывается.
- `routes` не импортируется другими слоями напрямую по имени файла — с ним общается только
  сгенерированный `routeTree.gen`, который затем подключает `app` (см.
  [`../app/DBP.md`](../app/DBP.md)).

## Структура файлов

Каждый файл — один узел дерева маршрутов: либо лист (монтирует одну страницу из `pages`),
либо layout-узел (монтирует общий каркас для вложенных маршрутов и содержит `Outlet` для них).
Имя файла кодирует путь в URL и вложенность по соглашению файлового роутера — это техническая
деталь роутера, а не архитектурное решение FSD.

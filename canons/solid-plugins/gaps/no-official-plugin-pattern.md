# Пробел: у Solid нет официального паттерна «плагин»

**Вопрос (заказ S1, вопрос 8):** заявляет ли Solid или его мета-фреймворк (SolidStart) позицию по плагинной/расширяемой архитектуре — или её нет?

**Ответ: официального паттерна «плагин» у Solid нет.** Solid даёт ПРИМИТИВЫ, из которых расширяемость собирается, но не предписывает архитектуру расширения и не называет её.

## Что перебрано

- Документация Solid: разделы про `<Dynamic>`, `createContext`, `createStore`, `lazy`/`Suspense`, `<ErrorBoundary>`, `runWithOwner` — каждый описывает СВОЙ примитив, ни один не говорит «вот так строится плагин».
- SolidStart: конвенции про роутинг, данные, серверные функции — не про расширяемость приложения плагинами.
- `eslint-plugin-solid`: правила про реактивность и владение, не про плагинную модель.

## Что есть вместо паттерна

Набор примитивов, ложащихся в роли контракта расширения (каждый выписан в `sources/`):

| роль в плагинной модели | примитив Solid | выписка |
|---|---|---|
| вклад компонентом | `<Dynamic>` | `solid-dynamic` |
| контракт host↔расширение | `createContext`/`useContext` | `solid-createcontext` |
| реестр вкладов | `createStore` | `solid-createstore` |
| ленивый вклад | `lazy` + `<Suspense>` | `solid-lazy` |
| забор вокруг сбоя | `<ErrorBoundary>` | `solid-errorboundary` |
| владение вне дерева | `runWithOwner`/`getOwner` | `solid-runwithowner` |
| поставка расширения пакетом | peer + `solid` export condition | `gaps/two-copies-of-solid-js` |

## Почему это пробел, а не недосмотр

Solid по устройству — набор реактивных примитивов, а не платформа с плагинной моделью (в отличие от OSGi или VS Code из фонда `../plugins/`, где модель расширения нормирована). «Плагин на Solid» — это КОМПОЗИЦИЯ примитивов, которую каждый проект собирает сам. Явного отказа иметь мнение Solid тоже не публикует — тема просто не поднята.

**Следствие для рамки:** плагинную архитектуру на Solid придётся спроектировать самим из перечисленных примитивов; готового предписанного паттерна, на который можно сослаться, нет. Это согласуется с выводом фонда `../plugins/`: плагинная модель картографического/прикладного движка рынком, как правило, не нормирована.

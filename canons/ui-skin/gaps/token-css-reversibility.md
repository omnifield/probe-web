# Пробел: ОБРАТИМОСТЬ трансляции токенов (из CSS обратно в документ)

**Заказ B, вопрос 6 (часть).** Объявлена ли обратимость: можно ли из готового CSS восстановить документ токенов?

## Что искали и что нашли

Трансляция описана как ОДНОнаправленная сборка «документ → вывод»:

- **Style Dictionary** — формат `css/variables` собирает `:root` из документа токенов; трансформы имени строят имя переменной из пути токена. Обратного разбора CSS в документ на просмотренных страницах Formats/Transforms не объявлено.
- **DTCG-формат 2025.10** — нормирует сам документ (токены, группы, ссылки), но не отображение в CSS и тем более не обратный путь.
- **Material 3, Tokens Studio** — про модель токенов и темы; про восстановление документа из CSS не говорят.

## Почему считаем это пробелом рынка

Инструменты позиционированы как СБОРЩИКИ: один источник истины (документ токенов) → много выводов под платформы. Обратный путь (CSS → документ) противоречит самой роли «единого источника»: если CSS правится вручную и разбирается обратно, источник истины раздваивается. Поэтому обратимость не заявлена — не по недосмотру, а потому что модель однонаправленная по замыслу.

## Граница поиска

Страницы Formats/Transforms Style Dictionary и обзорные страницы DTCG/M3/Tokens Studio на 2026-08-15. Не проверялись отдельные «reverse»-утилиты и импортеры (напр. импорт существующего CSS в токен-редакторы) — если такой инструмент объявит обратимость нормой, запись переводится в `sources/`. Пока — направление объявлено односторонним.

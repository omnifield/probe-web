**Сбор от 2026-08-15.** Расширение и изоляция УЖЕ приехавшего вида. По каждому из 8 вопросов: чем закрыт и что осталось.

## Находки статуса (правило 4 — заказ прямо предупреждал)

- **`@scope` НЕ в Scoping L1.** Опубликованный CSS Scoping Module L1 — это First Public Working Draft ОТ 2014 ГОДА (инкапсуляция теневого дерева). Современный `@scope` нормируется в CSS Cascade and Inheritance L6 (WD 06.09.2024). Приписать `@scope` старому Scoping L1 — готовая ошибка; разнесено на две выписки.
- **CSS Shadow Parts** — Working Draft (16.12.2025), при широкой реализации `::part`.
- **Open UI** (из гипотез заказа) в этот проход не выписан — по предупреждению заказа это работа сообщества, не рекомендация; статус выписывать отдельно при доборе.

## Проверка гипотез (правило 5)

- Гипотеза «`::theme` — точка расширения» — **не подтвердилась как норма**: только обсуждение (`gaps/theme-pseudo-element.md`).
- Гипотеза «у кого-то есть правило про версионирование внешности» — **почти не подтвердилась**: один частный случай (Radix токены), общего правила нет (`gaps/appearance-versioning-policy.md`).

## Что осталось не закрытым — честно

1. **Вопрос 8** — пробел (версионирование внешности).
2. **Вопрос 4** — частично: многомерность из одного источника есть, сравнение «пакет на бренд vs генерация» с обоснованием — нет.
3. **`::slotted`, слоты, слои как точки расширения** — механизмы известны, но отдельными дословными выписками в этом заходе не закреплены.
4. Не выписаны вторые свидетели из гипотез: Spectrum/Spectrum Web Components (`::part` + брендовые наборы), Salesforce Lightning, Material Web, Carbon, Ark UI/Park UI, Panda (расширение рецептов), Vanilla Extract, Open UI (статус!). Spectrum/Lightning — реальные кандидаты закрыть вопросы 4 и 8.

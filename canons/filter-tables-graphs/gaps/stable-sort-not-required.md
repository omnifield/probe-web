# Пробел: УСТОЙЧИВОСТЬ сортировки (stable sort) как требование почти никем не нормирована

**Заход tables, T6 отдельным пунктом спрашивал: говорит ли кто-нибудь про устойчивость сортировки (стабильный относительный порядок строк, равных по ключам) как ТРЕБОВАНИЕ. Ответ перебора: нет. Синтаксис сортировки нормирован широко (имя параметра, множественные ключи, направление, место null), но СТАБИЛЬНОСТЬ либо не упоминается, либо прямо объявляется негарантированной. Это важный отрицательный результат: полагаться на «сортировка сама устойчива» нельзя, и рынок этого не обещает.**

## Что проверено

- **Google AIP-132** (`sources/aip-132-order-by.md`) — нормирует `order_by` (список полей, `desc`-суффикс, умолчание — возрастание), но про устойчивость при равных ключах МОЛЧИТ. Требования стабильности нет.
- **SQL / PostgreSQL ORDER BY** (`sources/postgresql-order-by.md`) — прямо: гарантируется только заданный порядок; без ORDER BY порядок не определён; относительный порядок строк, равных по всем ключам ORDER BY, НЕ гарантирован. Стабильность достигается лишь добавлением уникального тай-брейкера (напр., первичного ключа) в конец списка сортировки.
- **OData `$orderby`** (`sources/odata-v4.01-url-conventions.md`) — задаёт выражения и направление, устойчивость не требует.

## Следствие (названо как граница, не как наш вывод о продукте)

Ни один из перебранных сводов не делает stable sort обязательным. Практический канон, вытекающий из текстов: чтобы порядок страницы был воспроизводим (что важно для курсорного листания — см. `sources/aip-158-pagination.md` и `sources/graphql-cursor-connections.md`), сортировку нужно делать ПОЛНОЙ, добавляя уникальный ключ-тай-брейкер. Но это следствие текстов SQL, а не отдельная норма «сортировка обязана быть стабильной» — такой нормы у рынка нет.

## Почему это результат

Вопрос закрыт отрицательно с перебором поимённо (AIP-132, SQL/PostgreSQL, OData): устойчивость как ТРЕБОВАНИЕ не нормирована; SQL даже явно снимает гарантию для равных ключей. Следующий заход не переспрашивает «а вдруг где-то требуется» по этим сводам — здесь ответ дан; открытым остаётся лишь ISO/IEC 9075 по платному тексту (PostgreSQL показал норму, но не тождество формулировок ISO).

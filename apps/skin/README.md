<h2 id="главное">🏠 Главное</h2>

🖼️ Живая витрина кита `@web-core/ui` — используйте, чтобы увидеть компонент не макетом и не
скриншотом, а настоящим рендером через реальный движок сборки (`@web-core/assembly`), тем же
путём, каким компонент получает любой продукт. 🎲 Рядом с показом — генератор фейковых данных по
io-схеме компонента, чтобы проверить его на разных данных, а не только на одном примере, вбитом
руками. Скин-редактор поверх той же механики — отдельный процесс (`.mcp/`, `@web-core/skin-mcp`,
своя дока), эта страница его не пересказывает.

<h2 id="анатомия">🧩 Анатомия</h2>

🗺️ У приложения нет импортируемой поверхности — «часть» здесь означает маршрут, а «адрес» — URL,
по которому эта часть открывается. Каждая часть ниже — свой файл в `src/routes/`.

| Часть                          | Адрес                            | Показывает                                            |
| ------------------------------ | --------------------------------- | ------------------------------------------------------ |
| Показ компонента (по умолчанию)| `/showcase/:component`            | первая объявленная сборка (см. `instanceOf`)            |
| Показ компонента (сборка)      | `/showcase/:component/:assembly`  | именно названную сборку                                |
| Витрина без выбора             | `/showcase`                       | подсказку выбрать компонент в дереве слева              |
| Лаборатория                    | `/lab`                            | заглушку — назначение экрана ещё не объявлено           |
| Корень                         | `/`                                | редирект на `/showcase`                                 |

📦 Внутри — слои FSD, каждая папка ровно с одним публичным входом (`index.ts`/`index.tsx`, снаружи
не видно ничего глубже него): `app/` — точка входа (`mountApp`, роутер, query-клиент), `pages/` —
раскладка воркспейса и сами экраны, `widgets/component/` — три отдельные панели (дерево кита,
показ, инпут), `entities/component/` — модель кита (атомы, паспорт компонента), рендерер и
фейк-генератор, `entities/showcase/` — голый слот показа, `shared/` — переключатель темы. `.mcp/`
— отдельный пакет (`@web-core/skin-mcp`), в граф импортов приложения не входит, свой процесс.

<h2 id="использование">🚀 Использование</h2>

✅ Три сценария покрывают то, чем реально пользуются с этим приложением: поднять витрину, открыть
конкретный компонент, прочитать, как фейк-генератор подключается к показу.

**Поднять витрину:**

```sh
pnpm --filter @web-core/skin-app dev
# http://localhost:5174 — редирект на /showcase
```

**Открыть компонент напрямую по адресу** (или кликом по дереву слева — оно ведёт туда же):

```
http://localhost:5174/showcase/button/base
```

**Фейковые данные по io-схеме активного компонента** (`entities/component/utils/fake-generator`,
подключено в `widgets/component/input`):

```ts
import { componentInfoAtom, generateFakeData } from "#/entities/component";
import { useAtom } from "@web-core/store";
import { createEffect } from "solid-js";

const info = useAtom(componentInfoAtom);

createEffect(() => {
  const state = info();
  if (state.status !== "done" || state.data === undefined) return;
  console.log(generateFakeData(state.data.io?.schema, state.data.component));
});
```

<h2 id="настройки">🎚️ Настройки</h2>

🔧 Настраивает витрину окружение Vite и флаги запуска — не отдельная сущность с общим списком.

| Настройка         | Где                                          | Тип      | По умолчанию                            |
| ------------------ | --------------------------------------------- | -------- | ---------------------------------------- |
| `VITE_PRESETS_URL` | `entities/component/model/info.ts`            | `string` | `http://127.0.0.1:8787/api/presets`      |
| `--port`           | `package.json`, `scripts.dev`, флаг Vite      | `number` | `5174` (`--strictPort` — второй не встанет тихо на соседний) |
| `--host`           | `package.json`, `scripts.dev`, флаг Vite      | `string` | `0.0.0.0`                                |

<h2 id="состояния">🎛️ Состояния</h2>

🚦 Реальный, ловимый статус один — состояние загрузки инфо о выбранном компоненте
(`componentInfoAtom`, `ResourceState` из `@web-core/store`). Ни одно значение здесь не придумано
этим приложением — форма целиком из движка стора.

| Состояние        | Метка                          | Где                          |
| ----------------- | ------------------------------- | ----------------------------- |
| Инфо загружается  | `status: "pending"`             | `componentInfoAtom`           |
| Инфо получено     | `status: "done"`, поле `data`   | `componentInfoAtom`           |
| Инфо не получено  | `status: "error"`, поле `error` | `componentInfoAtom` (например, служба пресетов не поднята) |

<h2 id="io">🔌 IO</h2>

↔️ Вход приложения — параметры маршрута и адрес службы пресетов; выход — настоящий DOM компонента
и (пока) фейковые данные в консоли, не в UI.

### 📥 Вход

| Источник                    | Форма                                          |
| ----------------------------- | ------------------------------------------------ |
| Параметры маршрута            | `{ component: string, assembly?: string }`       |
| `VITE_PRESETS_URL`             | адрес службы пресетов (`@web-core/skin/presets`) |
| Io-схема компонента            | `componentInfo(component).io?.schema` — вход фейк-генератора |
| `VITE_CHAT_URL` / `VITE_CHAT_TOKEN` | адрес бокса агента и общий токен витрины (`Authorization: Bearer`) |
| `VITE_CHAT_RECIPE` / `VITE_CHAT_PASSPORT` / `VITE_CHAT_AGENT` | чем заводится сессия агента; дефолты `сборка-скинов` / `опус-5` / `claude-code` |
| Логин и id сессии (`entities/user`) | заводятся на входе юзера и лежат рядом; логин едет в `X-User-Login` (без него 401), id — в адресе каждого запроса к боксу |

### 📤 Выход

| Источник                          | Отдаёт                                                     |
| ------------------------------------ | -------------------------------------------------------------- |
| `Renderer` (`RenderTree`)             | реальный DOM компонента, тем же движком, что у продукта         |
| `generateFakeData`                    | фейковый объект по io-схеме (сейчас — только `console.log`)      |

<h2 id="сборки">🏗️ Сборки</h2>

🧪 Тестов, доказывающих композицию, пока нет ни одного (`vitest.config.ts` настроен, `test/`
пуст) — то, что ниже, проверено вручную через dev-сервер и браузер, не автоматическим прогоном.
Это дыра, не постоянное положение дел — см. `ROADMAP.yaml`, категория «Не сделано».

| Композиция                                                    | Проверено (вручную)                                                    |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `Tree` → маршрут → `Preview` → `Renderer` → `RenderTree`          | клик по дереву кита меняет URL, показ перерисовывается настоящим движком   |
| `componentInfoAtom` → `Input` → `generateFakeData`                | смена активного компонента логирует новый фейковый объект по io-схеме      |

<h2 id="рецепт">🎨 Рецепт</h2>

🧩 Съёмный слой этого приложения — таблица подсказок фейк-генератора (`fake-generator/hints.ts`):
живёт СНАРУЖИ io-схемы компонента, по одной записи на компонент, и адресует конкретные поля,
которые схема не валидирует (обычный `z.string()` без зод-тегов — `zocker` тут угадывает вслепую).

```ts
// entities/component/utils/fake-generator/hints.ts
const HINTS: Readonly<Record<string, ComponentHints>> = {
  button: { label: { length: 10 } },
};
```

✨ Движок один и общий (`zocker`, читает зод-теги — email/телефон/имя и так далее прямо из
схемы) — подсказка не подменяет его, а точечно перекрывает генерацию ОДНОГО названного поля
названного компонента (`supply` по ссылке на схему этого поля), не трогая ни другие поля той же
схемы, ни другие компоненты. Компонент без записи в таблице генерируется как есть, вслепую —
ровно так же, как вело бы себя приложение без этого слоя вообще.

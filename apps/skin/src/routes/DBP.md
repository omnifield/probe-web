# `routes` — не отдельный слой FSD, а физическое расширение `app`

## Почему эта папка вообще существует отдельно

Канонический порядок слоёв FSD сверху вниз: `app → pages → widgets → features → entities →
shared`.
`routes` в этот список НЕ входит — это не бизнес-слой методологии, а техническое требование
роутера (`TanStack Router`). Концептуально то, что здесь лежит — часть `app`-слоя (композиция
роутинга), просто физически вынесенная в свою папку.

## Дерево задано явно, не именами файлов

Дерево маршрутов больше не кодируется в имени файла (`_workspace.showcase.$component.tsx`) —
явный конфиг `shared/configs/routes.config.ts` (`@web-core/router/virtual-file-routes`,
`rootRoute`/`layout`/`route`/`index`) описывает вложенность напрямую. Сами файлы маршрутов
(`createFileRoute(...)`) переехали и лежат РЯДОМ со страницей, которую монтируют —
`pages/showcase/route.$component.$tag.tsx` соседствует с `pages/showcase/index.tsx`, а не
собраны в одной плоской директории. В `routes/` остались только `__root.tsx` (корень дерева,
путь к нему указан в `rootRoute("__root.tsx", ...)` и резолвится относительно `routesDirectory`,
`./src/routes` по умолчанию) и этот файл.

Все файлы маршрутов — тонкие: `createFileRoute(...)`, импорт страницы из соседнего `./index`,
минимум логики.

## Правило импортов

- Файл маршрута импортирует страницу из того же каталога (`./index`) и из роутер-пакета
  (`@tanstack/solid-router`, `@web-core/router`).
- НЕ импортирует `widgets`/`entities`/`shared` напрямую в обход страницы — если маршруту нужен
  виджет или сущность, он должен прийти через страницу, которую этот маршрут монтирует, а не
  минуя её. Иначе смысл `pages` как единой точки композиции экрана размывается.
- Маршрут не импортируется другими слоями напрямую по имени файла — с ним общается только
  сгенерированный `routeTree.gen`, который затем подключает `app` (см.
  [`../app/DBP.md`](../app/DBP.md)).

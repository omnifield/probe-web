# @omnifield/probe-web-runtime

Рантайм probe-web: **`mount()`, контракт `#root` и механика подключения скина** — то, что
зовёт скелет приложения у потребителя. Первая из четырёх замороженных точек выпуска (контракт
зон — `kb:PROBEWEB-4`).

Пакет не знает ни про сборку, ни про стили, ни про компоненты: build-инструментов в его
зависимостях нет и быть не может — ради этого зона и отделена от `build`.

## Поверхность

```ts
import {
  mount,           // поднять приложение в #root
  restoreSkin,     // восстановить пресет и режим — ДО первой отрисовки
  applySkin,       // поставить пресет и/или режим и запомнить выбор
  readSkin,        // что стоит на корне сейчас
  checkStyleOrder, // приехал ли базовый CSS под стоящим пресетом
} from "@omnifield/probe-web-runtime";
```

Подпуть у пакета **один**: механика едет именованными экспортами той же точки, отдельного
пакета и отдельного подпути не заводим (`kb:PROBEWEB-13`). Всё остальное внутри — внутреннее
и ломается свободно.

**Заморожены две вещи — сигнатура `mount()` и идентификатор `#root`.** `main.tsx` едет к
потребителю классом `placed-once`: положен один раз и не обновляется никогда, поэтому вызовы
в нём живут вечно ровно в той форме, в какой их туда положили. Запрета на соседние экспорты
из этого не следует, но и они, оказавшись в скелете, замерзают вместе с ним — состав
поверхности меняет architect, а не зона.

## Контракт `#root`

Точку монтирования рантайм ищет **сам** — элемент с `id="root"` в документе:

```html
<div id="root"></div>
```

Идентификатора нет в сигнатуре намеренно: передай его аргументом — и заодно с вызовом
заморозится способ разметки страницы, а он обязан двигаться. Элемента нет — `mount()`
**падает с внятным сообщением**, а не рисует молча в пустоту:

```
[probe-web-runtime] mount(): в документе нет элемента #root.
Точку монтирования рантайм ищет сам — добавь в index.html <div id="root"></div>.
```

`#root` — часть замороженной поверхности наравне с самим экспортом. Менять его нельзя без
мажора и разговора с architect.

## Владение и очистка

`render()` из `solid-js/web` создаёт владеющий контекст (`createRoot`) и возвращает `dispose`.
Дока Solid прямо предупреждает: **без явного `dispose` вычисления не управляются и текут**
(фонд `solidJS/sources/solid-docs-ownership.md`).

Что решено и почему:

- **Наружу `dispose` не отдаётся.** Тип точки заморожен как `void`; вернуть ручку — значит
  изменить замороженную поверхность, а это разговор с architect, не решение внутри зоны.
- **Но и не выбрасывается.** Ручку держит сама зона — `WeakMap` «узел-хозяин → `dispose`».
  Модульная переменная тут не годится: она пережила бы сам узел и вечно держала бы замыкание
  над оторванным от документа деревом. Умер ключ-узел — умерла запись.
- **Повторный вызов на том же `#root`** (HMR, перезапуск) сначала **уничтожает** прежний
  корень и только потом монтирует новый. Инвариант зоны — «один документ, одно приложение»:
  `#root` в контракте один, и складывать в него корни стопкой значит держать живыми
  вычисления, до которых уже никто не дотянется.
- **Страница закрывается — уничтожать нечего:** корень умирает вместе с документом, и
  вешать ради этого `pagehide` было бы обрядом, а не очисткой.

Понадобится потребителю управляемый `dispose` (микрофронтенды, несколько приложений на
странице) — это заявка на изменение контракта, и адресат её architect.

## Механика подключения скина

Контракт — `kb:PROBEWEB-13`, инварианты — `kb:SKIN-7`, шов — `kb:SKIN-5`.

**Механика — удобство, а не путь к результату.** Четыре строки импорта и атрибут на `<html>`
работают в статической странице без сборки и без единой строки JS. Проверка на месте:
приложение, НЕ позвавшее ни одной функции ниже, но подключившее файлы, выглядит правильно.
Перестало быть верным — механика вышла за границу.

Отсюда же: приложение **без единого файла оформления** запускается и пригодно к работе
(инвариант 4). Мы не делаем оформление обязательным.

### Две вещи механика НЕ знает — их ей сообщают

Это не неудобство, а несущее свойство: и перечень пресетов, и имя маркерного токена
принадлежат чужим зонам и меняются без нашего ведома.

| что | кому принадлежит | почему не зашито у нас |
|---|---|---|
| перечень пресетов | `skin` (`products/`) | база не может зависеть от `products/` (`kb:PROBEWEB-4`): временная зона, обязанная уехать, оказалась бы вшита в фундамент |
| имя маркерного токена | `style` | литерал стал бы тихой связью — переименуют токен, и проверка начнёт врать, ничего при этом не покрасив |

Побочная выгода обоих решений одна: **чужой поставщик пресетов и чужая база встают в эту
механику без единой правки.**

Перечень передаётся **обычным массивом идентификаторов** — ровно тем, что механике нужно, и
ничем сверх. Названия, семена и файлы пресетов её не касаются: они нужны интерфейсу выбора, а
тот берёт их у `skin` напрямую, минуя нас. Единственный источник перечня остаётся один
(инвариант 11) — мы его не дублируем.

### Что зовёт скелет и в каком порядке

```html
<!-- index.html, в <head> — ДО первой отрисовки -->
<script type="module">
  import { restoreSkin } from "@omnifield/probe-web-runtime";
  restoreSkin({ presets: ["twitter"] });   // перечень приходит от skin
</script>
```

```ts
// main.tsx
import "@omnifield/probe-web-style/base.css";    // ← маркер приезжает здесь
import "@omnifield/probe-web-style/themes.css";
import "@probe-web/skin/presets/twitter.css";
import "@probe-web/skin/skin.css";

import { checkStyleOrder, mount } from "@omnifield/probe-web-runtime";

checkStyleOrder({ marker: "--space-4" });        // имя маркера приходит от style
mount(() => <App />);
```

**`restoreSkin()` — это та функция, которую скелет обязан позвать ДО первой отрисовки.**
Класс режима, поставленный после первого кадра, даёт вспышку светлой темы перед тёмной
(инвариант 3), а `mount()` зовётся после загрузки бандла, то есть заведомо позже первого
кадра. Закрыть вспышку изнутри `mount()` нельзя — это работа скелета, и доказывается она там
же (`tasker:PROBEWEB-53`).

Почему её МОЖНО звать так рано:

- синхронна, ничего не ждёт — ни загрузки бандла, ни готовности документа;
- не знает про Solid и не трогает `#root` — только `document.documentElement`, а он
  существует уже во время разбора страницы, когда `<body>` ещё нет;
- не спрашивает вычисленные стили, поэтому ей не нужен ни один подключённый лист. Этим она
  отличается от `checkStyleOrder()`, которой стили нужны по определению — потому это две
  разные функции, а не одна с флагом.

Ничего не запоминает: восстановление — не выбор человека, и записывать его как выбор значило
бы придумать за него решение, которого он не принимал.

### Пресет и режим ортогональны

`data-theme` отвечает на «какой костюм», класс `dark` — на «светло или темно», и одно не
зашито в другое (инвариант 3): `twitter-dark` отдельным пресетом удвоил бы перечень.

```ts
applySkin({ mode: "dark" });        // пресет не тронут
applySkin({ preset: "dense" });     // режим не тронут
applySkin({ preset: null });        // пресет снят — приложение вернулось на базу
```

Светлый режим — **отсутствие** класса, а не второй класс. `preset: null` — это «снять», а
отсутствующее поле — «не трогай»; состояние «пресета нет» настоящее, и выразить его надо уметь.

Выбор запоминается между заходами. `remember: false` нужен для случая «применили ЧУЖОЕ
умолчание»: тема, пришедшая снаружи, не должна становиться собственным выбором человека.

**Дерево не перемонтируется** (инвариант 9): меняются только значения на корне, поэтому
открытые панели, фокус и ввод переживают смену вида. Проба утверждает не «узел такой же», а
«узел тот же самый».

**Ни одного инлайнового стиля и ни одного `!important`** (инвариант 6). Мы ставим атрибут и
класс — это входные данные, а не оформление; иначе приложение потеряло бы право переопределять
наш вид обычным CSS.

### Проверка порядка подключения

Пресет без базового CSS даёт вид, где производные посчитаны от умолчаний. Выглядит это как
«скин почти работает» — **хуже явной поломки**, потому что чинить такое никто не идёт.

```ts
checkStyleOrder({ marker: "--space-4" });
// [probe-web-runtime] порядок подключения нарушен: пресет «twitter» стоит, а базового CSS
// нет — на корне не объявлен токен --space-4. Производные посчитаны от умолчаний, и вид
// будет «почти правильным» — это хуже явной поломки. Порядок импортов: базовый CSS →
// ступени темы → пресет → оформление.
```

| статус | что значит | шумит ли |
|---|---|---|
| `ok` | маркер на корне объявлен — база приехала | нет |
| `missing-base` | пресет стоит, а маркера нет — **порядок нарушен** | `console.error` |
| `no-skin` | ни базы, ни пресета — голый кит, заявленное свойство (инвариант 4) | нет |

**Что проверка видит и чего не видит.** Она отвечает на «база приехала или нет», а не на «в
каком порядке склеены листы»: настоящий порядок правил в каскаде из DOM не читается. Ловится
следствие, ради которого правило и заведено, — молча пропавшая база под стоящим пресетом.

**Не бросает и не останавливает приложение.** Механика — удобство, и диагностика вида не имеет
права ронять работающее приложение потребителя: она кричит в `console.error` и отдаёт разбор
значением. Что с ним делать — упасть в dev, показать плашку, промолчать — решает приложение.

Имя маркера, не похожее на кастом-свойство, — **отказ сразу**: такая проверка не нашла бы
маркер НИКОГДА и кричала бы на исправном приложении.

### Чего механика не делает

- **Не заводит ручек «на компонент»** (инвариант 10) — публичная поверхность вида это
  `data-variant`/`data-size`, и новый вариант появляется в `skin` ДЛЯ ВСЕХ.
- **Не предполагает локальных скинов** — производные вычисляются в `:root` и на контейнере не
  пересчитываются (инвариант 1). Это объявленное ограничение, а не забытая возможность:
  появится живой потребитель — вернёмся с его замером (`kb:PROBEWEB-13`).
- **Не делает НИЧЕГО на импорте.** `sideEffects: false` в манифесте — обещание трясуну;
  самоинициализация сделала бы его ложью, а трясун вырезал бы то, на что кто-то рассчитывает.
  Стережётся пробой в среде без DOM.

## Perf-трейсы

Молчат по умолчанию, включаются явным глобальным флагом:

```js
globalThis.__PROBE_WEB_RUNTIME_TRACE__ = true;
// [probe-web-runtime] mount — 1.83ms
```

Автоопределения по dev-режиму сборщика нет намеренно: пакет приезжает потребителю
зависимостью, а подстановку в файлы из `node_modules` Vite не делает — условие осталось бы
вечно ложным, то есть трейсы были бы мёртвым кодом.

## Установка

`solid-js` — **peer-зависимость**: две копии Solid в дереве ломают реактивность.

```
pnpm add @omnifield/probe-web-runtime solid-js
```

ESM-only, `"type": "module"`, `sideEffects: false`, в тарбол едет только `dist` и эта дока.

## Раскладка

```
packages/runtime/
├── src/
│   ├── index.ts            # ВСЯ поверхность наружу — и mount(), и механика скина
│   ├── skin-root.ts        # корень документа как среда, ВНУТРЕННЕЕ
│   ├── skin-memory.ts      # память выбора, ВНУТРЕННЕЕ
│   └── trace.ts            # perf-трейсы, ВНУТРЕННЕЕ (в exports не объявлено)
├── test/
│   ├── mount.test.tsx      # приложение поднимается в DOM (jsdom + JSX-трансформ)
│   ├── skin.test.ts        # механика скина (jsdom БЕЗ Solid — это несущее, см. ниже)
│   └── surface.test.ts     # поверхность и тарбол — перечнем, а не на глаз
├── tsconfig.json           # конфиг самого пакета (базу потребителю отдаёт зона build)
├── tsconfig.build.json     # эмит dist по src
└── vitest.config.ts        # три проекта: mount, skin, surface
```

Публичная поверхность объявлена ЦЕЛИКОМ в `src/index.ts`, а не собрана реэкспортом из
соседей: реэкспорт-бочка в `dist/index.d.ts` запрещена и стережётся пробой. Соседние модули
внутренние и в `exports` манифеста не объявлены.

## Проверки

```
pnpm run typecheck   # tsc --noEmit
pnpm run build       # dist
pnpm test            # сборка + все три проекта vitest
```

Тест зоны поднимает **настоящее** приложение на Solid в JSDOM и утверждает отрендеренный узел
в `#root`, отдельными кейсами — живую реактивность после монтирования, уничтожение прежнего
корня при повторном вызове и внятный отказ без `#root`.

Пробы механики скина стоят **отдельным проектом без Solid и без JSX-трансформа**, и это
несущее решение, а не экономия: механика обязана работать до монтирования и вне Solid, а
проба, поднимающая Solid, доказывала бы обратное тому, что мы утверждаем. Проверка порядка
подключения ставится настоящими листами стилей — она спрашивает ВЫЧИСЛЕННЫЙ на корне токен, и
подставленное значение проверяло бы саму подстановку.

Официальная `@solidjs/testing-library` здесь сознательно **не** используется (сверено
2026-08-08, фонд `solid-testing-library`): её `render` создаёт свой контейнер, а предмет
проверки ровно обратный — что рантайм находит точку монтирования сам, в документе. JSX-трансформ
и `resolve.conditions: ["development", "browser"]` взяты из доки как предписано.

# prompt

Черновой, первый заход (2026-08-30) — не готовый инструмент, каркас для проверки на реальном
агенте. Постановка user: механические данные (паспорт+editorInfo) агент получает как есть, чтобы
не лазить за ними сам; писать прозу и примеры — его дело, не таблиц.

**Этот генератор не пишет доку и не зовёт модель.** Он собирает ПРОМПТ — файл `out/<имя>.md` — а
прогоняет его через агента отдельный шаг (человек или Task-тул), не эта команда.

## Устройство

- **`kit-context.md`** — заметки об устройстве кита, ОДИН файл на весь кит, попадает в каждый
  промпт целиком. Ведёт user. Сейчас пустой (плейсхолдер) — наполнится после первого реального
  прогона, тем, чего агенту действительно не хватило.
- **`templates/component-prompt.md.hbs`** — сам текст промпта. Три части: контекст кита, сырые
  данные компонента (паспорт+editorInfo, без нарезки под таблицу — в отличие от
  `../templates/component-readme.md.hbs`), и задача. Черновая — донастройка после фидбека.
- **`prompt.mjs`** — обвязка: `discoverEntries` + `generateScaffoldFiles` + `fromEntryTemplate`,
  ничего сверх уже готового движка (`@probe-web/generators/scaffold`).

## Куда садится результат агента

`README.md` компонента, секция `## Notes` между `<!-- user:start -->`/`<!-- user:end -->` — тот же
маркер-блок, что переживает механическую регенерацию (`../README.md`). Один файл, не два.

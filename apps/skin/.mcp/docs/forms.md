# Форма (рецепт компонента)

Разведка перед `save_preset(kind:"form")`. Полный разбор терминов — README.md, раздел «Словарь».

## Прежде чем писать с нуля — найдите пример

В службе уже лежат настоящие, рабочие формы (`omnifield-*`). `list_components` даёт `group`/
`footprint` каждого компонента — у компонента с ТЕМ ЖЕ `group`/`footprint` почти наверняка уже
есть форма-эталон. `get_preset({kind:"form", name:"omnifield-<похожий>"})` — копируйте СТРУКТУРУ
(какие части/состояния тронуты, как устроены переходы), не значения.

## `check_form` — два прохода

1. **Ссылки** — та же проверка, что и у наряда: роль/переменная в рецепте реально существует у
   палитры.
2. **Адрес** — часть/состояние/настройка реально существуют в паспорте компонента (`get_passport`).

Опечатка в любом из двух — флав с адресом, не тихое неприменение. Нужна палитра для сверки ролей —
не назвали `paletteName`, берётся первая из службы (для настоящей проверки называйте явно).

## Теги варианта (`variantTags`)

Значение `recipe.variants` можно тегировать — например `error`/`success`/`warning` тегируются
`"status"`, а `primary`/`secondary`/`tertiary` — нет. Каждый тег сверяется со словарём
(`kind:"tag"`); значение без тега получает `["default"]`. При `ok:true` `check_form` отдаёт
`tagGroups` — тег → варианты, готовая раскладка для свайперов/переключателей на витрине.

## Если `ok:false`

`css` пропадает из ответа вместе с флавом — сигнал не противоречив: невалидный рецепт не должен
выглядеть частично рабочим.

# @web-core/style-tools

**Инструменты стилизации** локации `web-core`: комбинатор классов `cn`, реактивная обвязка
вариантов `createStyle` и реэкспорт `cva`.

Это **самостоятельная НЕОБЯЗАТЕЛЬНАЯ поставка**. Оформление вправе взять инструменты у нас,
взять у кого-то ещё или не брать вовсе — и остаться законным: скин, написанный без единого
нашего инструмента, обязан проходить все проверки (`PWEB-3`). Пока это не так, связь между
частями фреймворка развёрнута неверно.

## Что наружу

| точка | что даёт |
|---|---|
| `@web-core/style-tools` | `cn`, `createStyle`, реэкспорт `cva` и `VariantProps` |

Вход ровно один, подпутей нет. **CSS отсюда не едет вовсе**, и это проверяется пробой:
инструмент работает с ИМЕНАМИ классов, а значения — предмет другой поставки
(`@web-core/style`).

## Чего здесь нет и почему

**Зависимости на набор значений.** Ни импорта, ни строки в манифесте, ни имени токена в
коде — держит `test/independence.test.ts`. Обратная связь возвращается тихо: достаточно
одному импорту «на минуту, ради удобства» заехать сюда, и необязательность кончилась вместе
с правом скина не брать наши значения.

Обратной зависимости тоже нет: набор значений про инструменты не знает. Разрез идёт в обе
стороны — односторонний разрез держался бы обещанием.

## `cn` — почему не одним `clsx`

`clsx` собирает условные формы, `tailwind-merge` разрешает КОНФЛИКТЫ утилит:

```ts
cn("p-2", "p-4");                    // → "p-4"
cn("p-2", "px-4");                   // → "p-2 px-4"  (разные группы, обе живут)
cn("base", cond && "hidden");        // ложное выпадает
```

Без разрешения конфликтов переопределение стиля через проп `class` не работает: в атрибут
попадают оба класса, и выигрывает тот, что раньше в CSS, — то есть порядок правил вместо
порядка аргументов.

`cn` работает и без Tailwind: знание о конфликтных группах живёт внутри `tailwind-merge`,
а произвольные классы проходят насквозь.

## `createStyle` — варианты, которые пересчитываются

```tsx
import { createStyle, cva } from "@web-core/style-tools";

const button = cva("inline-flex p-2", {
  variants: { size: { sm: "text-sm", lg: "text-lg p-4" } },
  defaultVariants: { size: "sm" },
});

function Button(props: { size?: "sm" | "lg"; class?: string }) {
  const cls = createStyle(button, props);
  return <button class={cls()}>…</button>;
}
```

Пропсы читаются ВНУТРИ мемо, поэтому смена варианта пересчитывает класс, а не застывает на
значении момента вызова. Проп `class` потребителя идёт последним аргументом `cn` — при
конфликте утилит выигрывает он, а не вариант. Это единственный способ переопределить стиль
компонента снаружи, и потому он часть контракта, а не деталь реализации.

Префикс `create*` — конвенция Solid для реактивного примитива. `solid-js` — одноранговая
зависимость: обвязка живёт в реактивности приложения, а не приносит свою.

## Разработка

```bash
pnpm install
pnpm run build      # tsc → dist
pnpm run typecheck
pnpm run test       # build + vitest (dom + node)
```

Машинного pre-commit в репозитории нет: сборку, типы и пробы гоняем руками перед каждым
коммитом.

**Мутационные проверки** — каждая воспроизводится за минуту и прогонялась.

| что ломаем | что обязано покраснеть |
|---|---|
| в `src/cn.ts` убрать `twMerge`, оставить один `clsx` | `cn.test.ts` — конфликт утилит перестаёт разрешаться, побеждает порядок правил в CSS |
| в `src/create-style.ts` убрать `splitProps` и отдать `props` в варианты целиком | `create-style.test.ts` — `class` удваивается в атрибуте |
| в `src/create-style.ts` посчитать класс один раз, вне `createMemo` | `create-style.test.ts` — смена варианта и смена `class` перестают доезжать |
| в `src/create-style.ts` поставить `local.class` первым аргументом `cn` | `create-style.test.ts` — проп потребителя перестаёт перебивать вариант |
| в `src/index.ts` добавить импорт `@web-core/style` | `independence.test.ts` — поставка перестала быть самостоятельной |
| в `package.json` вписать пакет значений в `devDependencies` | `independence.test.ts` — раздел `dev` считается наравне с остальными |
| в `exports` манифеста добавить подпуть `./cn` | `types.test.ts` — вход у поставки перестал быть одним |

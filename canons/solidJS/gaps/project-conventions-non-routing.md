# Пробел: у Solid нет позиции по раскладке кода вне маршрутизации (и это не «явный отказ»)

**Вопрос (Q7).** Есть ли у Solid/SolidStart официальная позиция по раскладке файлов, именованию и структуре — или явный отказ иметь мнение.

## Что найдено

- **Предписано и закрыто первичным** (`sources/solidstart-conventions.md`): структура SolidStart-проекта (`src/`, `routes/`, `entry-client/server`, `app.tsx`) и file-based routing (динамические сегменты, catch-all, группы-скобки, layout по имени папки).
- **НЕ предписано:** где размещать компоненты, сервисы, хранилища состояния; как именовать не-маршрутные файлы; как резать приложение на слои. Официальной страницы с этим нет.

## Форма пробела: отсутствие, а не отказ

ТЗ различает две вещи: **явный отказ иметь мнение** (его надо выписать как предписание) и **простое отсутствие позиции**. Здесь — второе:

- дока НЕ содержит фразы уровня «Solid намеренно не навязывает структуру проекта» — такого заявления найти не удалось;
- вместо заявленной позиции есть **признанные пробелы самой доки**: `solidjs/solid-docs#842` («No mention of layout file naming convention») и `solidjs/solid-start#1148` («recommended to further optimize the directory structure»). Открытый тикет — признак, что тема не закрыта, а не что по ней принято решение молчать.

## Где искал

- `docs.solidjs.com`: разделы SolidStart (getting-started, routing, building-your-application) — конвенции есть только для маршрутизации/входов.
- Ядро `solid-js`: раздела о структуре проекта нет.
- Трекер `solidjs/solid-docs` и `solidjs/solid-start`: тема фигурирует как незакрытая (issues выше), а не как оформленная позиция.

## Почему это результат, а не «плохо искал»

Граница ясна: там, где Solid имеет мнение (маршрутизация), оно выписано; там, где не имеет (общая раскладка), нет ни предписания, ни явного отказа — есть открытые тикеты. Ждать «явного отказа» как ответа здесь нельзя: его нет. Правильный итог — зафиксировать, что рынок (в лице Solid) на этот вопрос официально не отвечает.
